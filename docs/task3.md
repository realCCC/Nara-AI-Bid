# 핵심 사용자 시나리오 및 워크플로우

## 시나리오 개요

입찰 업체 담당자가 공고 추천부터 제안서 생성까지 전체 프로세스를 체험하는 2개 주요 시나리오.

---

## 시나리오 1: 공고 추천 및 적합성 분석

시나리오명: "우리 회사에 맞는 입찰 공고 찾기"

ID: SC-001

상황:
- 입찰담당자가 아침에 출근해서 어떤 공고에 입찰해야 할지 판단 필요
- 매일 100~200개 공고 중 자사 역량과 맞는 것을 찾는 데 2~3시간 소비
- 수작업으로 진행해서 놓치는 기회가 많음

목표:
- 현재: 자사 역량에 맞는 공고를 수작업으로 하루에 1~2건만 발굴
- 기대: AI 추천으로 3~5건의 적합 공고를 5분 내에 추천받기 + 각 공고별 낙찰 가능성 분석
- 핵심 메리트:
  * 효율성: 같은 시간에 공고 검토 수량 5배 증가 (5건 -> 25건/월)
  * 의사결정: 낙찰 가능성 낮은 공고는 미리 필터링 (불필요한 제안서 작성 시간 절감)
  * 결과: 양(수량) + 질(선별) 결합 -> 수주 기회 극대화 -> 사업 수주확률 증가

사전 조건:
- 업체 프로필 정보 등록 완료 (기술 역량, 보유 인력, 과거 실적)
- 현재 진행 중인 공고 데이터가 시스템에 로드됨 (20~30개)

상세 흐름:

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|-----|---------|---------|-----|
| 1 | 대시보드 진입 후 "추천 공고 조회" 클릭 | 등록된 업체 프로필 로드 | Streamlit 대시보드 |
| 2 | 필터 선택 (선택사항: 예산범위, 지역, 기술분야) | 필터 조건 적용 후 매칭 엔진 시작 | 기술분야: IT, 클라우드, 보안 등 |
| 3 | - | 업체 프로필 벡터화 & 공고 요구사항 벡터화 | 임베딩 모델 사용 (RAG) |
| 4 | - | 코사인 유사도 계산으로 적합도 순위 산출 | 0~100% 스코어 |
| 5 | 추천 결과 확인 (Top 5 공고 테이블) | 추천 공고 3~5건 + 적합도 % + 추천 근거 제시 | 예: "RAG 경험 매칭: 92%" |
| 6 | 선택한 공고 상세 보기 클릭 | 공고 상세정보 + 회사와의 적합성 분석 표시 | 차트로 시각화 |
| 7 | "이 공고로 제안서 만들기" 버튼 클릭 | SC-002로 전환 (제안서 생성 시나리오) | 선택된 공고 ID 전달 |

입력 예시 (JSON):

{
  "회사명": "AI 데이터 스타트업",
  "설립연도": 2020,
  "기술보유": ["RAG", "LLM", "벡터DB"],
  "자격증": ["정보보안관리사"],
  "보유인력": {
    "AI개발자": 3,
    "풀스택": 2,
    "PM": 1
  },
  "과거실적_수행건수": 5,
  "필터": {
    "예산범위": [50000000, 300000000],
    "지역": "서울/경기",
    "기술분야": ["AI/데이터", "정보기술"]
  }
}

기대 출력:

추천 공고 Top 5

[1순위] AI 챗봇 솔루션 개발 | 적합도: 94%
- 공고번호: 2026-00015
- 예산: 2억원 | 마감일: 2026-10-15
- 필수자격: RAG 경험 / AI 프로젝트 3건 이상
- 추천근거: 보유 기술(RAG, LLM)과 100% 매칭, 과거 금융 챗봇 실적 5건 보유

[2순위] 데이터 분석 시스템 구축 | 적합도: 87%
- 공고번호: 2026-00021
- 예산: 1.5억원 | 마감일: 2026-10-20
- 필수자격: 빅데이터 경험 / Python
- 추천근거: AI 개발팀 규모(5명) 충분, 유사 프로젝트 실적 3건 보유

[3순위] 정보보안 AI 모니터링 | 적합도: 81%
(... 계속)

성공 기준:

기준 1: 추천 정확도
- 상위 3개 공고 중 최소 1개 이상이 담당자 기준으로 "적합하다"고 판단
- 검증 방법: 담당자 면접 평가

기준 2: 응답 시간
- 공고 추천 조회부터 결과 표시까지 5초 이내 완료
- 시스템 로그로 측정

기준 3: 사용성
- 기술 담당자 아닌 일반 담당자도 클릭 3~4회만에 추천공고 조회 가능
- 별도 설정/입력 없이 즉시 사용 가능

## 시나리오 2: 제안서 초안 자동 생성 및 검토

시나리오명: "선택된 공고에 대한 제안서 초안 만들고 수정하기"

ID: SC-002

상황:
- 입찰 담당자가 적합한 공고를 선택했음
- 이제 제안서를 작성해야 하는데, 공고마다 2~3시간 소비
- 회사소개, 기술방안, 조직구성 등을 매번 처음부터 작성
- 공고별로 포맷/스타일이 달라서 일관성 없음

목표:
- 현재: 공고별로 제안서 초안 작성에 2~3시간 소비
- 기대: AI가 초안 생성 (5분) -> 담당자 검토/수정 (30분)으로 단축
- 핵심 메리트:
  * 효율성: 제안서 작성 시간 70% 감축 (2-3시간 -> 35분)
  * 품질: 공고별 맞춤형 작성 + 평가기준 최적화 -> 기존 템플릿 대비 설득력 향상
  * 의사결정: 평가기준 대응 전략 제시로 각 항목별 강화 방향 명확화
  * 결과: 더 많은 공고에 제안 가능 + 각 제안서 경쟁력 향상 -> 수주확률 극대화

사전 조건:
- SC-001에서 특정 공고 선택 완료
- 업체 프로필 정보 시스템에 등록됨
- 선택된 공고의 상세 정보(과업내용, 평가기준, 필수자격) 준비됨

상세 흐름:

| 단계 | 사용자 행동 | 시스템 동작 | 비고 |
|-----|---------|---------|-----|
| 1 | SC-001에서 "제안서 만들기" 클릭 | 선택된 공고 ID + 업체 프로필 전달 | 컨텍스트 유지 |
| 2 | - | 공고 분석 Agent 시작 - 과업내용, 필수자격, 평가기준 파싱 | Claude 기반 분석 |
| 3 | - | 제안서 섹션별 자동 생성: 1) 회사소개 2) 수행방안 3) 추진일정 4) 조직구성 | 각 섹션 2~3분 내 생성 |
| 4 | "초안 생성됨" 알림 보면 초안 검토 | 마크다운 형식 초안 + 평가기준 매핑표 제시 | 수정 가능한 에디터 제공 |
| 5 | 초안에서 부족한 부분 수정 (선택사항) | 수정된 텍스트 즉시 반영, 단어 수 계산 | 실시간 미리보기 |
| 6 | "최적화 제안 요청" 버튼 클릭 (선택사항) | 평가기준별로 강화할 부분 AI 제안 | "기술력 40점 -> 50점으로 높이려면..." |
| 7 | 최종 확인 후 "다운로드" 클릭 | 제안서를 Word/PDF/마크다운 형식으로 다운로드 | 담당자가 외부 공유 가능 |

입력 예시 (JSON):

{
  "선택공고": {
    "공고번호": "2026-00015",
    "공고명": "AI 챗봇 솔루션 개발",
    "과업내용": "RAG 기반 자연어 처리 챗봇 개발 및 운영, 사용자 1000명 기준",
    "예산": 200000000,
    "마감일": "2026-10-15",
    "필수자격": ["AI 관련 프로젝트 3건 이상 수행", "RAG 기술 경험"],
    "평가기준": {
      "기술력": 50,
      "가격": 30,
      "회사실적": 20
    }
  },
  "업체프로필": {
    "회사명": "AI 데이터 스타트업",
    "설립연도": 2020,
    "기술보유": ["RAG", "LLM", "벡터DB"],
    "과거실적": [
      {
        "프로젝트명": "금융 챗봇 개발",

        "금액": 150000000,

      }

기대 출력 (마크다운):

# 제안서 초안: AI 챗봇 솔루션 개발

## 1. 회사 소개

당사 AI 데이터 스타트업은 2020년 설립되어 RAG 기반 자연어 처리 솔루션 개발에 특화된 업체입니다.

보유 기술: RAG, LLM, 벡터DB
핵심 인력: AI 개발자 3명, 프로젝트 매니저 1명

주요 실적:
- 금융 챗봇 개발 (2024.01~06, 1.5억원, 은행사)
- 고객 지원 챗봇 시스템 (2023.06~12, 1.2억원, 보험사)
- 문서 요약 AI 시스템 (2023.01~03, 8천만원, 미디어사)

## 2. 수행 방안

2.1 기술 아키텍처
본 프로젝트는 다음과 같은 기술 스택으로 진행됩니다:
- LLM: OpenAI GPT-4 (또는 Azure OpenAI)
- RAG 엔진: LangChain + Pinecone Vector DB
- 백엔드: Python FastAPI, PostgreSQL
- 프론트엔드: React + WebSocket (실시간 응답)

2.2 구현 프로세스
1. 요구분석 & 설계 (4주): 사용자 요구사항 파악, 시스템 설계서 작성
2. 개발 & 테스트 (8주): 챗봇 엔진 개발, 성능 최적화
3. 운영 및 튜닝 (2주): 사용자 피드백 반영, 파인튜닝

## 3. 추진 일정

| Phase | 기간 | 담당자 | 산출물 |
|-------|------|-------|--------|
| 요구분석 & 설계 | 4주 | PM, 아키텍트 | 설계서, 기술명세 |
| 개발 & 테스트 | 8주 | 개발팀(3명) | 소스코드, 테스트 리포트 |
| 인수인계 | 2주 | 전사 | 운영 매뉴얼, 교육 |

## 4. 조직 구성

| 역할 | 인원 | 경력 | 담당 업무 |
|------|------|------|---------|
| 프로젝트 매니저 | 1명 | 5년 | 일정/예산/리스크 관리 |
| AI 개발자 | 3명 | 3~5년 | RAG 엔진, 챗봇 개발 |
| QA 담당자 | 1명 | 2년 | 테스트, 품질보증 |

## 5. 평가기준 충족도

| 항목 | 배점 | 우리의 대응 | 점수 |
|------|------|----------|------|
| 기술력 | 50 | RAG 3건 실적 + 경험 많은 개발팀 | 48/50 |
| 가격 | 30 | 예산 내 적정가 제시 | 28/30 |
| 회사실적 | 20 | 유사 프로젝트 5건 이상 수행 | 18/20 |
| 합계 | 100 | | 94/100 |

제안서 초안 생성일: 2026-10-01
담당자 검토 필요: 부분 수정 권장

성공 기준:

기준 1: 초안 커버율
- 생성된 제안서가 공고 필수 항목(회사소개, 기술방안, 일정, 조직)의 80% 이상 포함
- 평가기준별 대응 항목 매핑 완료

기준 2: 시간 단축
- 초안 생성 시간: 5분 이내
- 담당자 검토/수정: 30분 내 완료 -> 총 35분 (기존 2-3시간 대비 70% 단축)

기준 3: 담당자 만족도
- 생성된 초안에서 50% 이상의 내용을 그대로 사용 가능
- 수정 필요 비율 < 30% 목표
