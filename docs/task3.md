# 핵심 사용자 시나리오 및 워크플로우

## 사용자 페르소나: Mid-Tech 담당자

### 대상 사용자
- **직무:** 입찰·영업 담당자 (중소 IT 기업)
- **기술 수준:** Mid-Tech (기술 비전공자, 하지만 기본 데이터 이해 가능)
- **특징:** 엑셀/JSON 파일 다룰 수 있음, UI 기본 필터/옵션 이해 가능

### 사용자의 Pain Point
- 매일 아침 100-200건의 공고 중 1-2건만 찾음 (2-3시간 소비)
- 공고 분석과 제안서 초안 작성이 반복 업무
- 담당자 경험에 따라 품질 편차 큼

## 시나리오 1: 공고 검토 및 선택 프로세스

### ID
SC-001

### 시나리오명
"하루 아침에 적합 공고 찾아 최종 선택하기"

### 상황
입찰 담당자가 매일 100~200건의 새로운 공고를 받아, 자사 역량과 맞는 공고를 **검토 → 선택**하는 과정이 2-3시간 소비됨. 수작업 기준 하루에 검토 가능 공고는 20~30건이고, 최종 선택은 1-2건에 불과함. 따라서 적합한 공고를 놓치는 경우가 빈번하고, 같은 인력으로는 월 처리량 30건 수준에서 벗어나지 못함.

### 목표
- **현재:** 공고 검토에 2-3시간, 담당자가 검토 가능한 공고는 월 30건 정도
- **기대:** AI 추천 + 담당자 최종 선택 30분 내 완료, 월 50건 처리 (1.7배 증가)
- **핵심 메리트:** 
  - 효율성: 공고 검토 + 선택 시간 87% 단축 (2-3시간 → 30분)
  - 의사결정: 신뢰도 높은 추천(90% 정확도) + 담당자 최종 판단
  - 결과: 시간 단축 + 양(수량 증가) + 질(객관적 선별) 결합 → 수주 기회 극대화

### 사전 조건
- 기업 프로필 정보 시스템에 등록 완료 (기술 스택, 보유 인력, 과거 프로젝트 실적)
- IT 용역 공고 20~30건이 정적 데이터셋으로 준비됨

### 시간 순서별 상세 흐름 (총 30분)

#### 09:00 ~ 09:05 (5분) - 입력 데이터 준비

**담당자 액션**: Streamlit 대시보드에 진입하여 기업 프로필 JSON 파일 업로드  
**시스템 동작**: 기업정보(기술 스택, 인력, 실적) 파싱 및 검증

**입력 데이터**:
- 회사명, 설립년도, 인력 규모
- 기술 보유: Java, Spring, React, PostgreSQL, AWS 등
- 자격증: ISO27001, CMMI Level 3 등
- 근무 인력 규모별 분포
- 최근 프로젝트 경험(기간, 예산, 결과)

#### 09:05 ~ 09:15 (10분) - 공고 분석 Agent 실행

**담당자 액션**: "공고 분석 시작" 버튼 클릭  
**System**: 공고 분석 Agent가 20~30건 공고 병렬 처리

**Agent 처리**:
1. 각 공고의 과업 내용, 자격요건, 평가기준을 자동 파싱
2. 공고를 기술 분류(웹 개발, 데이터 분석 등)로 카테고리화
3. 필수 자격요건 항목 추출 (기술 스택, 경험 연수, 인력 수, 자격증)

**출력**: 공고별 구조화된 데이터 (기술 분류, 필수 자격, 평가 기준)

#### 09:15 ~ 09:25 (10분) - 매칭 Agent 실행

**System**: 매칭 Agent가 기업 정보 vs 각 공고 요구사항 비교

**Agent 처리**:
1. 기술 스택 매칭: 기업 보유 기술 vs 공고 필수 기술의 교집합 비율
2. 경험 매칭: 기업 프로젝트 경험 vs 공고 요구 경험 적합도
3. 인력 매칭: 기업 현재 가용 인력 vs 공고 요구 인력 검증
4. 유사도 점수 계산 (0~100점, 기술 40% + 경험 40% + 인력 20%)

**출력**: 상위 5개 공고의 적합도 점수 + 추천 근거

#### 09:25 ~ 09:55 (30분) - 담당자 검토 및 최종 선택 (Human-in-the-loop)

**담당자 액션**: Streamlit 대시보드의 추천 공고 확인 및 선택

**상위 5건 추천 공고 표시**:
- 순위, 공고명, 예산, 마감일, 적합도 점수
- 클릭하면 상세정보 표시 (기술 일치도, 자격요건 충족도, 추천 근거)

**담당자 선택 기준**:
1. 기술 매칭: 우리 팀의 역량을 최대한 활용할 수 있는가? (기술 일치도 90% 이상)
2. 자격 충족: 필수 자격요건을 모두 충족하는가? (충족률 100%)
3. 적합도 점수: 85점 이상의 신뢰도 있는 공고인가?
4. 비즈니스 전략: 낙찰 확률과 수익성이 좋은가?

**최종 선택**: 위 기준을 종합하여 제안서를 작성할 공고 **1건 선택**

**승인 지점**: 담당자가 선택한 공고 확정 (DB에 기록)

#### 09:55 ~ 10:00 (5분) - 선택 결과 저장 및 다음 단계 준비

**System**: 선택된 공고 정보를 DB에 저장, SC-002로 세션 전달

**저장 데이터**: 공고 ID, 선택 시간, 담당자명, 선택 근거

**측정 방법**:

**판정 기준**: 정확도 **90% 이상** (270건 이상)  
**측정 시점**: PoC 검증 단계(5주차) 시작 시 자동화 테스트로 측정

- 담당자 검토 및 선택: 30분

**개선 후 소요시간**:

- 공고 분석(Agent): 10분 (83% 단축)
- 매칭 및 순위(Agent): 10분 (78% 단축)
- 담당자 검토 및 선택: 30분 (변화 없음)
- **총 55분 (0시간 55분)**

**단축율**: (140분 - 55분) / 140분 × 100 = **61% 단축**

**측정 방법**: 대표 공고 3건 실제 수행 시간 측정  
**판정 기준**: 평균 소요시간 **55분 이하** (또는 61% 이상 단축)  
**측정 시점**: PoC 검증 단계(5주차)에서 실제 담당자가 3건 처리

## 시나리오 2: 제안서 초안 자동 생성 프로세스

### ID
SC-002

### 시나리오명
"선택된 공고에 대해 제안서 초안 5분 만에 생성하고 담당자가 고도화하기"

### 상황
담당자가 SC-001에서 공고 1건을 선택함. 이제 제안서 초안을 작성해야 하는데, 기존에는 공고마다 3-4시간 소비됨. 회사소개, 기술방안, 일정계획, 조직구성 등을 매번 처음부터 작성해야 하고, 공고별로 평가기준이 다르기 때문에 매번 다른 접근이 필요함. 결과적으로 공고별 제안서 작성에 묶여서 더 많은 공고에 응찰할 수 없음.

### 목표
- **현재:** 공고별로 제안서 초안 작성에 3-4시간 소비, 월 처리량 30건
- **기대:** AI 초안 생성(20분) + 담당자 검토·수정(50분) = 총 90분(1시간 30분) 소요 → 월 처리량 50건 달성
- **핵심 메리트:**
  - 효율성: 제안서 작성 시간 68% 단축 (3-4시간 → 1시간 30분)
  - 품질: 공고별 맞춤형 자동화 작성 + 평가기준 대응표 자동 매핑 → 필수 항목 누락 방지(목표 80% 이상 커버율)
  - 의사결정: 평가기준별 강점 제시로 제안 전략 수립 시간 단축
  - 결과: 같은 인력으로 월 제출 공고 수 증가(30건 → 50건) + 각 제안서 경쟁력 향상

### 사전 조건
- SC-001에서 특정 공고 1건 선택 완료 (공고 ID, 선택 시간 기록됨)
- 기업 프로필 정보 시스템에 등록 완료 (회사 소개, 기술 보유, 인력 구성, 과거 프로젝트 실적)
- 선택된 공고의 상세 정보 준비됨 (과업 내용, 평가 기준, 필수 자격 요건, 마감일, 예산)

### 시간 순서별 상세 흐름 (총 90분)

#### 10:00 ~ 10:05 (5분) - 입력 데이터 준비

**담당자 액션**: SC-001에서 "제안서 만들기" 버튼 클릭  
**System**: 선택된 공고 ID + 기업 프로필 정보 자동 전달 (세션 유지)

**입력 데이터**:
- 공고 정보: 공고명, 과업 내용, 평가 기준, 필수 자격, 예산, 마감일
- 기업 정보: 회사명, 기술 스택, 인력 구성, 과거 프로젝트 실적

#### 10:05 ~ 10:25 (20분) - 제안서 작성 Agent 실행 (4개 섹션 병렬 생성)

**System**: 제안서 작성 Agent가 4개 섹션을 병렬로 생성

**Agent 처리** (LangGraph Supervisor + Sub-Agent 구조):
- **Sub-Agent 1**: 회사소개 섹션 → 기업명, 핵심역량, 유사 실적 추출
- **Sub-Agent 2**: 기술방안 섹션 → 공고 요구사항 분석 + 기업 기술 매칭 → 시스템 구성 제시
- **Sub-Agent 3**: 추진일정 섹션 → 공고 기간 분석 + Phase별 일정 구성
- **Sub-Agent 4**: 조직구성 섹션 → 기업 인력 기반 팀 구성 제안

**출력**: 마크다운 형식의 제안서 초안 (4개 섹션)

#### 10:25 ~ 10:30 (5분) - 평가기준 대응표 자동 생성

**System**: 매칭 Agent가 공고 평가 기준과 제안서 내용을 매칭

**Agent 처리**:
1. 공고에 명시된 평가 기준 항목 추출 (예: 기술력 50%, 가격 30%, 실적 20%)
2. 생성된 제안서의 각 섹션이 평가 기준의 어느 부분을 충족하는지 매칭
3. 각 평가 기준별 강점/약점 분석

**출력**: 평가기준 대응표 (엑셀 형식)

#### 10:30 ~ 11:20 (50분) - 담당자 검토 및 고도화 (Human-in-the-loop)

**담당자 액션**: Streamlit 대시보드에서 생성된 제안서 초안과 평가기준 대응표 검토

**검토 프로세스**:
1. 자동 생성된 초안 읽기 (20분)
   - 회사명, 기술명, 인력 정보 정확성 확인
   - 숫자 일치성 검증 (예산, 인력 수, 프로젝트 기간)
   - 공고 요구사항과의 적합성 재확인

2. 필요시 수정 (20분)
   - 회사 기밀정보 추가 또는 제거
   - 실적사례 상세화 (예: "금융 챗봇" → "국민은행 금융 챗봇 개발(2024년, 월 사용자 500만, 만족도 98%)")
   - 기술방안의 차별화 포인트 강조
   - 약점 보완 전략 추가 (예: 가격 경쟁력 약점 → 효율적 인력 구성으로 보완)

3. 평가기준 대응 검증 (10분)
   - 각 평가 기준별 대응 전략이 명확한지 확인
   - 점수 예상치가 합리적인지 검토

**승인 지점**: 담당자가 최종 검토 후 "제안서 완성" 버튼 클릭 → 상태를 "검토 완료"로 저장

#### 11:20 ~ 11:30 (10분) - 최종 제안서 생성 및 저장

**System**: 담당자 수정사항 반영 후 최종 제안서 생성

**출력**:
- Markdown 형식 최종 제안서
- 평가기준 대응표 (Excel)
- 공고별 제안서 버전 관리 (수정 이력 기록)

**저장 위치**: 공고별 폴더 (공고ID_회사명_v1.0)

### 성공 기준 및 KPI 측정

#### KPI 1: 제안서 초안 커버율 (80% 이상) - **Task2에서 정의한 핵심 KPI**

**정의**: 공고 필수 항목 반영률 (평가기준 및 과업요구사항 포함도)

**측정 방법**:
- 정답셋: IT 용역 공고 30건 × 가상 기업 10개사 = 300건 조합
- 각 공고별로 **필수 포함 항목 체크리스트** 사전 작성:
  - 회사소개: 기업명, 핵심역량, 유사 실적 명시
  - 기술방안: 시스템 아키텍처, 보안대책, 개발 단계 명시
  - 추진일정: 최소 3개 Phase 이상, 담당 인력 명시
  - 조직구성: PM, 개발자, QA 최소 3개 직무 이상 명시
  - 평가기준 대응표: 각 평가 항목별 강점 및 대응 전략 명시

- 자동 검사: 생성된 제안서가 체크리스트 항목을 포함하는지 검증 (정규표현식 또는 키워드 매칭)
- 계산식: (포함된 필수 항목 수) / (전체 필수 항목 수) × 100

**판정 기준**: 커버율 **80% 이상** (300건 조합 중 240건 이상)  
**측정 시점**: PoC 검증 단계(5주차) 시작 시 자동화 테스트로 측정

#### KPI 2: 업무 시간 단축 (68% 이상) - **Task2에서 정의한 핵심 KPI**

**정의**: 제안서 초안 작성부터 최종 검토까지 소요되는 시간 단축

**현재 소요시간**:
- 입력 데이터 준비: 5분
- 제안서 초안 수작업 작성: 180분 (회사소개, 기술방안, 일정, 조직)
- 평가기준 대응 분석(수작업): 30분
- 담당자 검토 및 수정: 60분
- 최종 제안서 생성: 10분
- **총 285분 (4시간 45분)**

**개선 후 소요시간**:
- 입력 데이터 준비: 5분
- 제안서 초안 자동 생성(Agent): 20분 (89% 단축)
- 평가기준 대응표 자동 생성: 5분 (83% 단축)
- 담당자 검토 및 수정: 50분 (17% 단축, 일부는 여전히 필요)
- 최종 제안서 생성: 10분
- **총 90분 (1시간 30분)**

**단축율**: (285분 - 90분) / 285분 × 100 = **68% 단축**

**측정 방법**: 대표 공고 3건에 대해 실제 담당자가 전체 프로세스 수행 후 시간 기록  
**판정 기준**: 평균 소요시간 **90분 이하** (또는 68% 이상 단축)  
**측정 시점**: PoC 검증 단계(5주차)에서 담당자가 실제 3건 처리

#### KPI 3: 생성 초안의 실용성 (수정 필요도 20% 이하) - **품질 및 재사용성**

**정의**: 생성된 제안서 초안 중 실무에 바로 사용 가능한 정도

**측정 방법**:
- 담당자 5인이 자동 생성된 초안 10건을 검토
- 각 문장/섹션을 분류:
  - (A) 완벽함: 수정 불필요
  - (B) 경미한 수정: 오류 수정만 필요 (숫자, 표기 등)
  - (C) 의미 있는 재작성: 내용 수정 필요
  - (D) 완전히 새로 작성: 항목 전체 재작성

- 계산: (A + B 항목의 단어 수) / (전체 초안 단어 수) × 100

**판정 기준**: 
- 재사용 가능 비율(A+B) **80% 이상**
- 의미 있는 재작성 필요(C+D) **20% 이하**
- 담당자 만족도 점수 **3.5점 이상**(5점 만점)

**측정 시점**: PoC 검증 단계(5주차) 이후 담당자 피드백

- 담당자 월 업무시간: 약 160시간 (동일)
- 월 처리량: 160시간 ÷ 3시간 = **약 53건** (1일 약 5건)

**결과: 같은 인력 투입으로 월 처리량 30건 → 50건으로 확대 (약 1.7배 증가)**

## 부록 E. 검증 계획

### 정량 평가 (자동)

**SC-001 (공고 추천)**
- **응답 속도:** 300건 조합 중 90% 이상이 5초 내 완료, 평균 < 2초
- **추천 정확도:** 정답셋 300건(30 공고 × 10 기업)에 대해 90% 달성
  - 정답 판정: 담당자 3인 중 2인 이상이 "적합"이라고 판단한 공고
- **사용성:** 실제 담당자 5인이 튜토리얼 없이 3클릭 내로 작업 완료

**SC-002 (제안서 생성)**
- **생성 속도:** 300건 조합 중 90% 이상이 5분 내 완료, 평균 < 3분
- **초안 커버율:** 필수 4개 섹션 모두 포함 85% 이상, 평가기준 매핑 정확도 80% 이상
- **수정 필요 비율:** 담당자 5인이 검토한 10건 초안 중 수정 필요 항목 < 30%

### 정성 평가 (사용자 피드백)

**담당자 인터뷰 (5인 × 2시간)**
- SC-001: 추천 공고 적합도, 낙찰 가능성 판단 도움 수준, UI 이해도
- SC-002: 생성 초안 완성도, 재사용 가능 비율, 수정 소요 시간, 전반 만족도 (5점 척도)

**초안 품질 검증**
- 실제 공고 3건에서 자동 생성된 초안을 담당자가 직접 수정하며 소요 시간 측정
- 수정 필요 항목 분류: (a) 미완성, (b) 경미한 수정, (c) 완벽, (d) 개선 제안

### 최종 검증 (Gate)
- 실제 공고 3건 × 가상 기업 5개(15건) End-to-End 테스트
- 통과 기준: 모든 성공 기준 달성 + 담당자 만족도 3.5/5.0 이상
- 담당자가 검수 후 실제 제출 가능한 수준 달성 여부 확인

## 부록 F. 시나리오 → 모듈/컴포넌트 매핑

### SC-001: 공고 추천 시스템

| 시나리오 단계 | 모듈명 | 담당 컴포넌트 | 입력 | 출력 |
|-------------|-------|-----------|-----|-----|
| 1-2 | **파일 수신 & 검증** | FileUploadModule | JSON 파일 | 파싱된 기업정보 객체 |
| 3 | **필터 처리** | FilterModule | 사용자 선택 (예산, 지역) | 필터링된 공고 목록 |
| 4 | **유사도 계산** | EmbeddingModule + SimilarityModule | 기업정보 + 공고 | 유사도 스코어 배열 |
| 5-6 | **결과 렌더링** | ResultTableComponent | 유사도 스코어 | 상위 5건 공고 테이블 |

**모듈 간 의존성:**
```
FileUploadModule → EmbeddingModule → SimilarityModule → ResultTableComponent
                ↘ FilterModule ↗
```

### SC-002: 제안서 초안 생성 시스템

| 시나리오 단계 | 모듈명 | 담당 컴포넌트 | 입력 | 출력 |
|-------------|-------|-----------|-----|-----|
| 1-2 | **공고 분석** | TenderAnalysisAgent | 공고 ID + 공고 상세정보 | 필수자격, 평가기준 구조화 |
| 3 | **섹션별 생성** | SectionGeneratorAgent (4개 병렬) | 공고분석 결과 + 기업정보 | 각 섹션 Markdown 텍스트 |
| 4 | **통합 & 렌더링** | ProposalAssemblyModule | 4개 섹션 + 매핑표 | 최종 Markdown 초안 |
| 5 | **인라인 편집** | MarkdownEditorComponent | 사용자 입력 | 수정된 Markdown |
| 6 | **파일 내보내기** | ExportModule | 최종 Markdown | 로컬 파일 (MD, 향후 Word/PDF) |

**모듈 간 의존성:**
```
TenderAnalysisAgent → SectionGeneratorAgent (병렬, 4개)
                    ↓
                ProposalAssemblyModule → MarkdownEditorComponent → ExportModule
```
