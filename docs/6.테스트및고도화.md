## **주요 문제 해결 및 기술 리서치 (테스트 단계)**

5번 PoC 이후 테스트 과정에서 발견된 한계와 병목을 해결하기 위해 리서치하고 적용한 방법을 기록합니다. (최종 갱신 2026-10-29)

| **이슈 구분** | **문제 상황 및 원인** | **리서치 및 해결 과정 (Reference & Solution)** |
| --- | --- | --- |
| **품질/검색** | 역량 키워드 문자열 일치(S2)만으로는 '행사'와 '북페스티벌·엑스포·콘퍼런스'처럼 표현이 다른 공고를 놓침 | **리서치:** Hybrid Search(Dense + BM25)와 RRF(Reciprocal Rank Fusion) 조사<br>**적용:** BGE-M3 dense 검색 + kiwipiepy 형태소 BM25 + 룰 점수 순위를 RRF(k=60)로 합침. 임베딩을 못 쓰면 BM25만 쓰는 `keyword_fallback` 경로로 자동 전환 |
| **품질/점수** | BGE-M3 코사인 값이 업체마다 0.40~0.66으로 달라 고정 임계값으로 의미 점수를 만들 수 없음 | **리서치:** 업체별 분포 기반 정규화 검토<br>**적용:** 업체 키워드↔전체 공고 443건 코사인 분포의 백분위(50%→0점, 97%→1점)로 선형 변환. 단일 최대값 대신 상위 3개 키워드 평균을 써서 노이즈 감소 (실측 AUC 0.84→0.86). S2는 문자열 일치와 의미 점수 중 큰 값 |
| **품질/키워드** | 업체 역량 키워드가 짧은 단어(행사·운영 등)라 임베딩·문자열 일치 모두 공고명 어휘와 잘 맞지 않음 | **리서치:** Query Expansion·HyDE(가상 문서 임베딩) 조사<br>**적용:** **키워드 의미 프로필** — LLM이 키워드별 설명문·유사어·가상 공고명을 만들어 S2 의미 매칭·문자열 일치·PDF 청크 검색에 사용. 코드가 넓은 단어·중복을 거르고, 유사어는 검색 문장에는 붙이지 않음(붙였더니 상위 10건이 나빠짐) |
| **품질/리랭크** | Cross-encoder(bge-reranker-v2-m3) 순서만 쓰면 룰 점수를 무시함 (실측: 룰 57.8점 공고가 3위) | **리서치:** 리랭커와 1차 검색 순위의 결합 방식 조사<br>**적용:** 상위 15건만 리랭크하고, 리랭크 순위와 기존 RRF 순위를 다시 RRF로 합침. 리랭커 로드 실패 시 생략하고 기존 순서 유지 |
| **품질/환각** | RAG 순위를 LLM 한 번의 판단에 의존 → 순위 근거를 다시 확인할 장치가 없음 | **리서치:** Self-Correction·Reviewer Agent 패턴 조사<br>**적용:** 상위 5건을 재평가하는 **검증 서브에이전트** 노드 추가. 출력에 없는 공고ID·누락·중복이 있으면 결과를 버리고 원순위 유지 |
| **품질/검증 재현율** | 1차 검증 에이전트는 부적격 공고를 절반가량 놓침 (플래그 재현율 0.54). 놓친 6건 중 4건은 근거 청크가 아예 입력에 없었음 | **리서치:** 검색 전 구조 기반 필터링(섹션 우선 선택) 검토<br>**적용:** 추천 단계와 **다른 근거**(참가 조건 필드 + 자격 청크)로 불충족 조건(issues)을 찾게 하고, 자격 청크는 '참가자격' 섹션 → 지역제한·대기업·중견 핵심 문장 → 검색 순으로 6개 선택. 원문 대조 + 업체 프로필 충돌을 통과한 issue만 남겨 해당 공고를 뒤로 보냄 → **재현율 0.54 → 0.97** (1-5 참고) |
| **품질/청킹** | 500자 고정 분할이 조항 중간을 자르고, 청렴계약 같은 상투 문구 청크가 검색 상위를 차지. PDF 18개는 단어마다 제어 문자가 붙어 인용 대조 실패 | **리서치:** 문서 구조 기반(Structure-aware) 청킹 조사<br>**적용:** 조항 기호(`1.`·`가.`·`○`·`※`) 단위 300~800자, 문장 겹침, 상투 문구·페이지 번호·제어 문자 제거, 섹션 제목을 붙인 `search_text`로 검색 (1-6 참고) |
| **사용자 의도** | 같은 업체라도 이번에 찾는 분야·예산·지역이 다른데 추천 조건에 반영할 방법이 없음 | **리서치:** LangGraph `interrupt` 기반 HITL 설계 재검토<br>**적용:** 추천 전 **AI 맞춤 인터뷰(HITL ⓪)**. LLM이 업체정보로 문항·선택지를 만들되 선택지마다 정해진 효과(예산·가중치·지역·일정·주력 분야·확장어·제외어) 하나만 붙이고 코드가 검증. 마지막 자유 입력은 LLM이 같은 효과로 해석. 건너뛰면 기본값 |
| **사용자 확인** | 추천 근거를 봐도 담당자가 공고서의 자격·제출서류를 다시 읽어야 확정 가능 | **리서치:** Human-in-the-loop 확인 단계 설계<br>**적용:** **담당자 확인 체크리스트(HITL ①)** — 공고 필드 + AI가 공고서에서 뽑은 조건(원문 대조) + AI 자격 의심 사항·검증 issue. 전부 체크해야 선택 확정, 이력에 저장 |
| **속도/지연** | CPU에서 BGE-M3로 공고 443건을 임베딩하면 첫 계산에 약 2~3분. 검증 단계가 RAG와 같은 청크를 또 임베딩해 BGE 첫 추천에서 검증만 253초 | **리서치:** 임베딩 캐시 전략 조사<br>**적용:** `(모델명, 문장)` 해시 키로 공고 벡터를 `data/emb_cache.npz`에, 공고서 청크 벡터를 공고별 `data/chunk_vecs/`에 저장. 검증·체크리스트·평가항목 추출이 RAG 청크 벡터를 재사용. 캐시는 git에 포함해 다른 PC에서 재계산 불필요 |
| **관측성** | 추천 1회에 LLM·검색·리랭크·검증이 얽혀 어느 단계가 느리거나 틀렸는지 알기 어려움 | **리서치:** LangSmith 트레이싱 조사<br>**적용:** 그래프 노드·LLM 호출·검색/RAG 도구(BM25·BGE·리랭커·청킹·출처 대조)를 한 트레이스로 기록, 업체ID 태그 (`backend/tracing.py`). 위 253초 병목도 트레이스로 발견 |
| **보안/가드레일** | 인터뷰 답변·API 입력이 그대로 그래프에 들어가면 잘못된 값이나 다른 업체 작업에 접근 가능 | **적용:** 인터뷰 답변은 문항별 허용 값만 남기는 화이트리스트 처리, `thread_id` 소유 업체 확인(404), 이미 답한 인터뷰 재요청 차단(409), 체크리스트 미확인 시 선택 차단(400) |

## 4. 기타 문제 해결 사례

| 이슈 | 원인 | 해결 |
| --- | --- | --- |
| 인터뷰를 모두 건너뛰면 그래프가 재개되지 않음 | `Command(resume={})`처럼 빈 dict를 넘기면 LangGraph가 인터럽트 ID 매핑으로 해석 | 재개 값을 항상 `{"answers": {...}}` 형태로 감쌈 |
| 테스트용 가짜 벡터가 실제 캐시에 섞일 위험 | 임베딩 캐시가 모듈 전역 + 디스크 파일 | 테스트 fixture에서 캐시 경로를 임시 폴더로 바꾸고 전역 캐시 초기화 |
| 인터뷰 확장어가 LLM 판단을 흐림 | 확장어를 업체 프로필에 직접 넣으면 LLM이 업체 실제 역량으로 오해 | 확장 프로필은 키워드 일치(S2)·BM25·청크 검색에만 쓰고, LLM에는 원래 프로필 전달 |
| 유사어를 검색 문장에 붙이면 추천이 나빠짐 | 검색 문장이 길어져 dense·리랭커 초점이 흐려짐 | 유사어는 S2 문자열 일치·청크 검색에만, 검색 문장은 공고명 어휘로 쓰도록 프롬프트 수정 |
| 검증 에이전트 오탐 ('확인 불가'류 issue) | LLM이 프로필에 없는 값(소기업 여부)이나 선호(계약방식)를 자격 충돌로 보고 | 충돌 항목을 코드로 4종에 제한하고 issue의 업체 값이 실제 프로필에 있어야 인정 → 정밀도 0.95 유지 |
| LLM 인용에 `(파일 p.쪽) [섹션]` 표시가 섞임 | 청크 앞에 붙인 위치 표시를 LLM이 인용으로 복사 | 프롬프트에 금지 명시 + 출처 대조 시 표시를 떼고 비교 |
| 청크 벡터 일괄 계산이 중단됨 | 업체 10개 상위 공고를 한 번에 임베딩하면 CPU 메모리 부족 | `warm_chunk_vectors.py --company`로 업체별 나눠 실행 |
| Windows 콘솔에서 데모 스크립트 출력 오류 | 출력 문자열의 `—`(U+2014)를 cp949로 인코딩하지 못함 (`UnicodeEncodeError`) | 실행 시 `PYTHONIOENCODING=utf-8` 설정 (스크립트 자체 수정은 다음 단계) |
| 패키지 이름이 역할을 드러내지 않음 | E2E 단계에서 `frontend/`와 나란히 둘 서버 코드가 `app/`에 있음 | `app/` → `backend/`로 이동, 에이전트별 노드는 `backend/agents/`로 분리 |
