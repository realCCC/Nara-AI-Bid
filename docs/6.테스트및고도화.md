## **주요 문제 해결 및 기술 리서치 (테스트 단계)**

5번 PoC 이후 테스트에서 발견한 한계와 해결 방법을 정리합니다. (최종 갱신 2026-11-02)

| **이슈** | **문제** | **해결** |
| --- | --- | --- |
| **검색** | 키워드 문자열 일치로는 '행사' ↔ '북페스티벌·엑스포' 같은 다른 표현을 놓침 | Dense(BGE-M3) + BM25(kiwipiepy) + 룰 점수를 RRF로 결합. 임베딩 실패 시 BM25만 사용 |
| **점수 정규화** | 코사인 값 분포가 업체마다 달라 고정 임계값 불가 | 업체별 백분위로 정규화, 상위 3개 키워드 평균 (AUC 0.84→0.86) |
| **키워드 확장** | 역량 키워드가 짧아 공고명과 잘 안 맞음 | LLM이 키워드별 설명·유사어·가상 공고명 생성(HyDE). 유사어는 검색 문장엔 안 붙임 |
| **리랭크** | Cross-encoder 순서만 쓰면 룰 점수 무시 | 상위 15건만 리랭크 후 기존 순위와 다시 RRF |
| **검증 재현율** | 검증 에이전트가 부적격 공고 절반을 놓침 (재현율 0.54) | 참가자격 섹션 우선으로 근거 청크 선택 + 원문·프로필 대조된 issue만 인정 → **0.97** (1-3) |
| **청킹** | 500자 고정 분할이 조항을 자르고 상투 문구가 검색 상위 차지 | 조항 기호 단위 300~800자, 상투 문구·제어 문자 제거 (1-4) |
| **사용자 의도/확인** | 이번 입찰 조건 반영·자격 확인 수단 없음 | HITL ⓪ AI 맞춤 인터뷰, HITL ① 담당자 확인 체크리스트(전부 체크해야 선택) |
| **속도** | 검증 단계가 같은 청크를 재임베딩해 253초 | 공고 벡터 캐시 + 청크 벡터 pgvector 저장·단계 간 재사용 |
| **1단계 본문 검색** | PDF 본문을 1단계 검색에 넣으면 나아질지 | `BODY_SEARCH=1` 옵션 구현, nDCG 0.904→0.908로 차이 없어 기본값 끔 |
| **제안서 환각** | LLM이 없는 실적·인증을 지어낼 수 있음 | 업체 문서 근거 검색 후 작성, 인용 원문 대조, 근거 없으면 `[AI 초안·검토 필요]` |
| **관측성** | 어느 단계가 느리거나 틀렸는지 모름 | LangSmith로 노드·LLM·검색 도구 트레이싱 (253초 병목 발견) |
| **가드레일** | 잘못된 입력·타 업체 작업 접근 가능 | 답변 화이트리스트, `thread_id` 소유 확인(404), 재요청 차단(409), 미확인 선택 차단(400) |

## 1. LLM 답변 품질 평가 및 개선

환경: Windows(CPU), Python 3.11, Azure OpenAI gpt-4.1, BGE-M3·bge-reranker-v2-m3. 업체 `C001` 외 평가용 10개, 공고 443건.

### 1-1. 하이브리드 검색 전후 (C001 상위 10건)

- `keyword_fallback`: 한미친선 축제, USG 직무박람회 등 '축제'·'운영' 단어 일치 위주
- `semantic`: 산림박람회, 국제 심포지엄, 북페스티벌 등 **5건 교체** — 단어는 다르지만 같은 행사 대행 유형
- 판정: 정성적으로 개선. 정답 라벨이 없어 정량 판정은 남은 과제

### 1-2. LLM 근거 출처 통과율

| 실행 | 통과율 |
| --- | --- |
| 5번 PoC | 25/39 (64%) |
| 추천 함수 직접 호출 | 34/40 (85%) |
| 그래프 실행 | 16/40 (40%) |

- 원인: LLM이 필드명 접두어(`tender.`)를 빼고 출력, PDF 인용에 위치 표시·제어 문자가 섞임
- 조치: 위치 표시 제거 후 대조, 제어 문자 제거. 필드 접두어 문제는 남은 과제
- 화면 노출 근거는 출처 확인된 것만 쓰므로 확인율 100%

### 1-3. 검증 에이전트 정량 평가 (`scripts/eval_verify.py`)

업체 10개 상위 5건 스냅샷, 정답셋 50건(부적격/적격-비추천/추천), 3회 평균. **라벨은 Claude 초안 → 담당자 확인 전 잠정치.**

| 지표 | 검증 전 | 1차 검증 | 강화 후 |
| --- | --- | --- | --- |
| nDCG@5 | 0.917 | 0.943 | **0.993** |
| 부적격 하위 배치율 | 0.643 | 0.893 | **1.000** |
| 플래그 정밀도 / 재현율 | – | 1.00 / 0.54 | **0.95 / 0.97** |

- 재현율 개선은 프롬프트보다 **입력 근거(자격 청크) 선택**의 영향이 컸음
- 정답셋 유효성 확인: 엉터리 검증기(무조치·무작위)는 하위 배치율 0.50~0.64, 라벨을 뒤집으면 0.09 → 정답셋이 좋고 나쁜 검증을 구별함
- 업종이 다른 공고 20건 주입 시 플래그 9/20 → **18/20** (업종 비교 버그 수정 후)
- nDCG@5는 무조치도 0.917이라 변별력이 작음 → 하위 배치율·정밀도/재현율을 주 지표로 사용

## 4. 기타 문제 해결

| 이슈 | 원인 → 해결 |
| --- | --- |
| 인터뷰 전부 건너뛰면 재개 안 됨 | 빈 dict를 인터럽트 매핑으로 해석 → `{"answers": {...}}`로 감쌈 |
| 확장어가 LLM 판단을 흐림 | 확장어는 검색에만 쓰고 LLM엔 원래 프로필 전달 |
| 검증 오탐 | 충돌 항목을 4종(소재지·중소기업·업종·금액)으로 제한 |
| 맞는 업종 issue가 버려짐 | JSON 공백 차이 → 공백 제거 후 비교 (플래그 9→18/20) |
| 청크 벡터 일괄 계산 중단 | CPU 메모리 부족 → 업체별 분할 실행 |
