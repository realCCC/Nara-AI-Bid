핵심 사용자 시나리오 및 워크플로우

중소 IT 기업의 입찰·영업 담당자는 매일 올라오는 공고를 검토해 응찰할 공고를 고르고, 고른 공고마다 제안서 초안을 처음부터 작성합니다. 이 문서는 이 반복 업무를 AI Agent가 돕는 2가지 핵심 시나리오(SC-001 공고 추천, SC-002 제안서 초안 템플릿 생성)의 사용자 여정과 KPI를 정의합니다. **메인 시나리오는 SC-001**이며, SC-002는 담당자가 이어서 작성할 초안 템플릿까지만 생성합니다 (2.문제정의및서비스계획 범위 결정). 모듈 구조·개발 환경 등 설계 세부는 4.상세설계및개발환경구축에서 다룹니다.

## 사용자 페르소나: Mid-Tech 담당자

### 대상 사용자
대상 사용자는 중소 IT 기업의 입찰·영업 담당자입니다. 기술 비전공자이지만 기본적인 데이터는 이해하는 Mid-Tech 수준으로, 엑셀·JSON 파일을 다룰 수 있고 웹 화면의 기본 필터와 옵션을 이해합니다.

### 사용자의 Pain Point
1. **공고 탐색 시간**: 매일 올라오는 많은 공고 중 적합한 공고를 찾는 데 오랜 시간을 씁니다.
2. **반복 업무**: 공고 분석과 제안서 초안 작성을 공고마다 처음부터 반복합니다.
3. **품질 편차**: 담당자 경험에 따라 공고 선별과 제안서 품질의 편차가 큽니다.

## 시나리오 1: 공고 검토 및 선택 프로세스

### ID
SC-001

### 시나리오명
"아침에 적합 공고 찾아 최종 선택하기"

### 상황
입찰 담당자가 새로 올라온 공고 중 자사 역량과 맞는 공고를 **검토 → 선택**해야 한다. 수작업으로는 검토할 수 있는 공고 수가 제한되어 적합한 공고를 놓치는 경우가 생기고, 같은 인력으로는 처리량을 늘리기 어렵다.

### 목표
| 구분 | 내용 |
|------|------|
| 현재 | 공고 분석·자격 확인·순위 결정을 모두 수작업으로 수행 |
| 기대 | 분석·매칭·순위는 Agent가 수행하고, 담당자는 추천 결과 검토와 최종 선택만 수행 |
| 효율성 | 공고 검토 + 선택 시간 단축 (**[목표값]** 업무 시간 50% 이상 단축) |
| 의사결정 | 근거가 붙은 추천(**[목표값]** 추천 정확도 90% 이상) + 담당자 최종 판단 |
| 기대 효과 | 같은 시간에 더 많은 공고를 객관적으로 선별해 수주 기회 확대 |

### 사전 조건
- 기업 프로필 정보 시스템에 등록 완료 (기술 스택, 보유 인력, 과거 프로젝트 실적)
- IT 용역 공고 30건이 정적 데이터셋으로 준비됨

### 단계별 상세 흐름

#### 1단계 - 입력 데이터 준비

**담당자 액션**: React 화면에 진입하여 기업 프로필 JSON 파일 업로드  
**시스템 동작**: 기업정보(기술 스택, 인력, 실적) 파싱 및 스키마 검증

**입력 데이터**:
- 회사명, 설립연도, 인력 규모
- 기술 보유: Java, Spring, React, PostgreSQL, AWS 등
- 자격증: ISO27001, CMMI Level 3 등
- 직무별 인력 분포
- 최근 프로젝트 경험(기간, 예산, 결과)

#### 2단계 - 공고 분석 Agent 실행

**담당자 액션**: "공고 분석 시작" 버튼 클릭  
**System**: 공고 분석 Agent가 공고 30건 병렬 처리

**Agent 처리**:
1. 각 공고의 과업 내용, 자격요건, 평가기준을 자동 파싱
2. 공고를 기술 분류(웹 개발, 데이터 분석 등)로 카테고리화
3. 필수 자격요건 항목 추출 (기술 스택, 경험 연수, 인력 수, 자격증)

**출력**: 공고별 구조화된 데이터 (기술 분류, 필수 자격, 평가 기준)

#### 3단계 - 매칭 Agent 실행

**System**: 매칭 Agent가 기업 정보 vs 각 공고 요구사항 비교

**Agent 처리**:
1. 기술 스택 매칭: 기업 보유 기술 vs 공고 필수 기술
2. 경험 매칭: 기업 프로젝트 경험 vs 공고 과업내용 적합도
3. 인력 매칭: 기업 가용 인력 vs 공고 요구 인력
4. 적합도 점수 계산: 0-100점, 기술 40% + 경험 40% + 인력 20% **[초기 설정값]** (기술·경험을 핵심 요소로 본 값, Phase 4 정답셋 결과로 조정)

**출력**: 상위 5건 **[초기 설정값]** 공고의 적합도 점수 + 추천 근거 (KPI 기준 상위 3건 + 비교용 2건)

#### 4단계 - 담당자 검토 및 최종 선택 (Human-in-the-loop ①)

**담당자 액션**: React 화면의 추천 공고 확인 및 선택

**상위 5건 추천 공고 표시**:
- 순위, 공고명, 예산, 마감일, 적합도 점수
- 클릭하면 상세정보 표시 (기술 일치 항목, 자격요건 충족 여부, 추천 근거)

**담당자 선택 기준**:
1. 자격 충족: 필수 자격요건을 모두 충족하는가? (미충족 공고는 시스템이 사전 제외)
2. 기술 매칭: 우리 팀의 역량을 최대한 활용할 수 있는가?
3. 적합도 점수: 다른 후보 대비 점수와 근거가 충분한가?
4. 비즈니스 전략: 수익성과 수행 여력이 맞는가?

**최종 선택**: 위 기준을 종합하여 제안서를 작성할 공고 **1건 선택**

**승인 지점**: 담당자가 선택한 공고 확정 → LangGraph `interrupt`에서 재개

#### 5단계 - 선택 결과 저장 및 다음 단계 준비

**System**: 선택된 공고 정보를 LangGraph State(thread)에 저장, SC-002로 전달

**저장 데이터**: 공고 ID, 선택 시각, 선택 근거

### 상세 흐름 테이블

| 단계 | 담당자 행동 | Agent/System 처리 | 출력 |
|------|-----------|------------------|------|
| 1 | 화면 진입 → JSON 업로드 | 기업정보 파싱·검증 | 기업 프로필 확인됨 |
| 2 | "공고 분석 시작" 클릭 | 공고 분석 Agent 실행 | 공고 구조화 데이터 |
| 3 | 대기 (진행 상태 확인) | 매칭 Agent 실행 | 상위 5건 추천 공고 |
| 4 | 추천 공고 5건 확인, 상세보기 | 기술/자격/근거 표시 | 매칭 분석표 |
| 5 | 공고 1건 최종 선택 (HITL ①) | 선택 결과 검증·저장 | 선택 확정 |
| 6 | "제안서 만들기" 클릭 | SC-002로 전환 (같은 thread 유지) | 제안서 작성 준비 |

### 성공 기준 및 KPI 측정

SC-001은 메인 시나리오이므로 KPI 1(추천 정확도), KPI 1-2(자격 필터 정확성), KPI 1-3(추천 근거 설명 가능성)을 **1순위 KPI**로 둡니다.

#### KPI 1: 추천 정확도 (90% 이상) - **2.문제정의및서비스계획 1순위 KPI**

**정의**: 상위 3건 중 '추천' 라벨 공고 1건 이상 포함 비율

**측정 방법**:
- 정답셋: IT 용역 공고 30건 × 가상 기업 10개사 = 300조합
- 정답 판정: 담당자 1인이 각 조합에 **부적격 / 적격-비추천 / 추천** 3단계 라벨과 판단 사유 1줄을 사전 기록 (기준: 2.문제정의및서비스계획 '적합 공고 정의')
- 계산식: (추천 상위 3건 중 '추천' 라벨 공고가 1건 이상인 기업 수) / (전체 기업 수 10) × 100
- 오류 분석: 상위 3건에 '부적격'이 들어가면 자격 필터 문제, '적격-비추천'이 들어가면 적합도 점수 문제로 분류

**판정 기준**: 정확도 **90% 이상** (기업 10개사 중 9개사 이상)  
**판정 주체**: 자동 — 상위 3건과 정답 라벨 대조, 정확도 계산, 오류 유형 분류 / 사람 — 300조합 3단계 라벨과 판단 사유 사전 작성 (정답 기준)  
**측정 시점**: Phase 4(7-8주차) 자동화 테스트

#### KPI 1-2: 자격 필터 정확성 ('부적격' 추천 0건) - **2.문제정의및서비스계획 1순위 KPI**

**정의**: 필수 자격을 충족하지 못하는 공고가 추천 목록에 들어가지 않는지 여부

**측정 방법**:
- 측정 대상: 기업 10개사 × 추천 상위 5건 = 50건
- 계산: 추천 상위 5건 중 정답 라벨이 '부적격'인 공고 수 합계
- 함께 기록: 규칙 기반 Eligibility 판정(`match_qualifications`)과 '부적격' 라벨의 일치율 (300조합). 불일치 사례는 공고 필수자격 데이터 오류인지 판정 규칙 오류인지 분류

**판정 기준**: **0건**  
**판정 주체**: 자동 — 정답 라벨 대조와 일치율 계산 (최종 판정) / 사람 — 정답 라벨 사전 작성 (KPI 1과 공유)  
**측정 시점**: Phase 4(7-8주차) 자동화 테스트

#### KPI 1-3: 추천 근거 설명 가능성 (출처 확인 95% 이상) - **2.문제정의및서비스계획 1순위 KPI**

**정의**: 추천 근거가 실제 입력 데이터(기업 프로필, 공고 필드)로 설명되는지 여부

**측정 방법**:
- 측정 대상: 기업 10개사 × 추천 상위 5건 × 근거 3-4개
- 매칭 Agent가 근거마다 출처 필드와 값을 함께 출력 (위 기대 출력의 '출처' 열)
- 자동 대조: 출처 필드가 실제로 존재하고, 근거에 쓴 값(기술명, 실적명, 인원, 금액)이 그 필드 값과 일치하는지 확인
- 계산식: (출처가 확인된 근거 수 / 전체 근거 수) × 100

**판정 기준**: **95% 이상** **[초기 설정값]** (Phase 4 1차 측정 후 조정)  
**판정 주체**: 자동 — 출처 필드 대조 (최종 판정) / 사람 — 출처 불일치 근거만 검토  
**측정 시점**: Phase 4(7-8주차) 자동화 테스트

#### KPI 2: 업무 시간 단축 (50% 이상) - **2.문제정의및서비스계획 업무 KPI**

**정의**: 공고 검토 + 선택에 소요되는 시간 단축

**측정 항목** (수작업 vs 서비스 각각 기록):
- 공고 분석 (수작업 vs 공고 분석 Agent)
- 매칭 및 순위 결정 (수작업 vs 매칭 Agent)
- 담당자 검토 및 선택 (양쪽 모두 담당자)

**계산식**: (수작업 시간 − 서비스 사용 시간) / 수작업 시간 × 100  
**측정 방법**: 대표 공고 3건을 담당자 1인이 두 방식으로 수행하고 시간 기록 (수작업·서비스 소요시간 모두 **[실측 예정값]**)  
**판정 기준**: SC-001 + SC-002 합산 **50% 이상 단축**  
**판정 주체**: 자동 — Agent 실행 시간 로그 기록 / 사람 — 수작업 수행 시간과 검토·선택 시간 기록 (최종 단축률 산출)  
**측정 시점**: Phase 4(7-8주차)

#### KPI 3: 담당자 만족도 (3.5점/5점 이상) - **사용자 신뢰도**

**정의**: 추천된 공고가 담당자에게 얼마나 유용한지 평가

**측정 방법**: 
- 담당자 1인이 추천 결과를 5단계 평가 (1점 전혀 부적합부터 5점 매우 적합까지)
- 추천의 신뢰도, 근거의 명확성, 화면 사용 편의성 평가

**판정 기준**: 평균 만족도 **3.5점 이상** (5점 척도 중간값보다 높은 수준으로 팀 설정)  
**판정 주체**: 자동 — 없음 (점수 평균 계산만) / 사람 — 5단계 평가와 인터뷰 (최종 판정)  
**측정 시점**: Phase 4(7-8주차)

## 시나리오 2: 제안서 초안 템플릿 생성 프로세스

### ID
SC-002

### 시나리오명
"선택된 공고에 맞춘 제안서 초안 템플릿을 받아 담당자가 이어서 작성하기"

### 상황
담당자가 SC-001에서 공고 1건을 선택함. 이제 제안서를 작성해야 하는데, 회사소개, 기술방안, 일정계획, 조직구성의 골격을 매번 처음부터 잡아야 하고, 공고별로 평가기준이 다르기 때문에 목차도 매번 달라짐. 결과적으로 공고별 제안서 작성에 묶여서 더 많은 공고에 응찰할 수 없음.

### 목표
| 구분 | 내용 |
|------|------|
| 현재 | 제안서 골격(목차, 회사소개, 평가기준 정리)을 공고마다 수작업으로 처음부터 작성 |
| 기대 | 시스템이 **고정 템플릿에 공고·기업·매칭 결과 값을 삽입**해 초안 템플릿(섹션 4개 + 평가기준 대응표)을 만들고, 담당자는 다운로드 후 `[확인 필요]` 자리를 채움 |
| 범위 | 완성형 제안서가 아님. LLM으로 문장을 생성하지 않음. 추천된 공고에서 제안서 작성이 시작될 수 있다는 **연결성**을 보여주는 보조 기능 |
| 효율성 | 제안서 골격 작성 시간 단축 (**[목표값]** SC-001 + SC-002 합산 업무 시간 50% 이상 단축) |
| 품질 | 공고 평가항목과 기업 정보가 템플릿에 빠짐없이 들어감 (**[목표값]** 필수 입력 항목 반영률 100%) |
| 기대 효과 | 같은 인력으로 대응 가능한 공고 수 증가, 담당자 경험과 무관하게 같은 골격에서 작성 시작 |

### 사전 조건
- SC-001에서 특정 공고 1건 선택 완료 (공고 ID, 선택 시각 기록됨)
- 기업 프로필 정보 시스템에 등록 완료 (회사 소개, 기술 보유, 인력 구성, 과거 프로젝트 실적)
- 선택된 공고의 상세 정보 준비됨 (과업 내용, 평가 기준, 필수 자격 요건, 마감일, 예산)

### 단계별 상세 흐름

#### 1단계 - 입력 데이터 준비

**담당자 액션**: SC-001에서 "제안서 만들기" 버튼 클릭  
**System**: 선택된 공고 ID + 기업 프로필을 같은 thread의 State에서 자동 로드

**입력 데이터**:
- 공고 정보: 공고명, 과업 내용, 평가 기준, 필수 자격, 예산, 마감일
- 기업 정보: 회사명, 기술 스택, 인력 구성, 과거 프로젝트 실적

#### 2단계 - 초안 템플릿 생성 (고정 템플릿 + 입력값 삽입)

**System**: 제안서 템플릿 모듈이 고정 HTML 템플릿에 입력값을 삽입해 섹션 4개를 만듦. **LLM을 호출하지 않음**

| 섹션 | 삽입하는 입력값 | `[확인 필요]`로 남기는 자리 |
|------|---------------|-----------------------|
| 1. 회사소개 | 기업 프로필: 회사명, 설립연도, 보유 기술, 인증, 과거 실적 표 | 회사 비전·차별화 포인트 |
| 2. 수행방안 | 공고 평가항목(기술력)을 목차(`<h3>`)로, 항목별로 SC-001 매칭 결과의 관련 기업 근거(기술·실적) | 항목별 수행 방안 본문 |
| 3. 추진일정 | 고정 단계(분석·설계 / 개발·테스트 / 운영·이관) + 공고 과업기간 | 단계별 기간 |
| 4. 조직구성 | 기업 보유인력(역할별 인원) | 투입 인력·역할 분담 |

평가항목별 관련 기업 근거는 SC-001에서 이미 계산한 BGE-M3 유사도(평가항목 ↔ 기업 기술·실적)로 고르며, 유사도가 임계값 미만이면 `[확인 필요]`로 둡니다. 추천 단계의 결과를 제안서에서 다시 쓰므로 두 시나리오가 자연스럽게 연결됩니다.

**출력**: 섹션별 HTML 조각 4개 (`<section>` 단위, 삽입값은 HTML 이스케이프)

#### 3단계 - 평가기준 대응표 생성

**System**: 공고 평가기준을 행으로 하는 고정 표 템플릿에 값을 삽입

1. 공고 평가항목·배점을 그대로 행으로 삽입 (예: 기술력 50점, 가격 30점, 실적 20점)
2. 평가항목별 대응 섹션 번호와 관련 기업 근거(2단계와 같은 매칭 결과) 삽입
3. 근거가 없는 항목은 `[확인 필요]`로 표시

**출력**: 평가기준 대응표 (HTML `<table>`)

#### 4단계 - 미리보기 및 다운로드

**담당자 액션**: React 화면에서 초안 템플릿과 대응표를 미리보기로 확인한 뒤 "다운로드" 클릭

- 화면에서는 섹션을 편집하지 않습니다. `[확인 필요]` 자리 작성과 수정은 다운로드 후 담당자가 수행합니다.
- 템플릿 삽입 방식이라 같은 입력이면 결과가 같으므로 "다시 생성"과 확정 단계(HITL ②)는 두지 않습니다. LLM 생성을 도입하는 확장 단계에서 HITL ②를 추가합니다.

**출력**:
- 초안 템플릿 HTML (섹션 4개 + 평가기준 대응표, 인쇄용 CSS 포함한 단일 `.html` 파일)

**저장 파일명**: `공고ID_회사명_v1.0.html`

### 상세 흐름 테이블

| 단계 | 담당자 행동 | System 처리 | 출력 | 역할 |
|------|-----------|------------------|------|------|
| 1 | "제안서 만들기" 클릭 | 공고+기업정보+매칭 결과 State에서 로드 | 데이터 준비 완료 | System |
| 2 | 대기 (즉시 완료) | 고정 템플릿에 입력값 삽입 | 섹션별 HTML 4개 | 제안서 템플릿 모듈 |

| 섹션 편집·WYSIWYG | **확장** | 화면 내 섹션별 수정, 리치 에디터 |
| PDF/Word 변환 | **확장** | 1차에는 브라우저 인쇄(PDF로 저장)로 대체 |

### 성공 기준 및 KPI 측정

SC-002의 KPI는 **보조 KPI**입니다. 생성 품질이 아니라 "추천된 공고에서 바로 제안서 작성을 시작할 수 있는가"만 확인합니다.

#### KPI 1: 초안 시작 가능 여부 (필수 입력 항목 반영률 100%) - **2.문제정의및서비스계획 보조 KPI**

**정의**: 초안 템플릿이 오류 없이 생성되고, 공고와 기업의 필수 입력 항목이 빠짐없이 들어갔는지 여부

**측정 방법**:
- 측정 대상: 공고 30건 × 각 공고의 추천 1순위 기업 = 초안 템플릿 30건 (실제 사용 흐름과 동일)
- 자동 검사 1 (생성): 30건 모두 HTML 파싱 성공, 섹션 4개 + 대응표 존재
- 자동 검사 2 (반영): 아래 항목을 공고 JSON·기업 프로필 값에서 바로 뽑아 HTML에 들어 있는지 확인. 별도 체크리스트를 사람이 만들 필요 없음
- 계산식: 초안별 (반영된 항목 수 / 전체 항목 수) × 100 → 30건 평균

| 섹션 | 필수 입력 항목 (출처) |
|------|-------------|
| 회사소개 | 회사명, 보유 기술, 과거 실적명 (기업 프로필) |
| 수행방안 | 공고 기술 평가항목 전부가 목차로 등장 (공고 `평가기준`) |
| 조직구성 | 역할별 인원 (기업 `보유인력`) |
| 평가기준 대응표 | 공고 평가항목·배점 전부가 행으로 등장 (공고 `평가기준`) |

**판정 기준**: 30건 모두 생성 + 평균 반영률 **100%** (템플릿 삽입 방식이라 누락이 있으면 버그로 봄)  
**판정 주체**: 자동 (최종 판정) / 사람 — 없음  
**측정 시점**: Phase 2부터 회귀 테스트로 상시 확인, Phase 4에 최종 측정

#### KPI 1-2: 초안 근거성 (프로필에 없는 사실 기재 0건) - **2.문제정의및서비스계획 보조 KPI**

**정의**: 초안에 쓴 사실 항목이 기업 프로필에 근거하는지 여부. 템플릿이 프로필 값만 삽입하므로 구조상 0건이어야 하며, 삽입 로직 오류를 잡는 확인용

**측정 방법**:
- 측정 대상: KPI 1과 같은 초안 30건
- 사실 항목 추출: 실적명, 발주처, 금액, 기간, 인원 수, 보유 자격·인증
- 자동 대조: 추출 항목을 기업 프로필 JSON 값과 문자열·숫자 비교 → 불일치 항목 목록 생성

**판정 기준**: **0건** (허위 기재는 감점·제재 위험)  
**판정 주체**: 자동 — 불일치 목록 생성 (최종 판정) / 사람 — 불일치가 나오면 원인 확인  
**측정 시점**: Phase 4(7-8주차)

#### KPI 2: 업무 시간 단축 (50% 이상) - **2.문제정의및서비스계획 업무 KPI**

**정의**: 제안서 초안 골격(목차, 회사소개·조직구성 표, 평가기준 대응표) 작성에 소요되는 시간 단축. 본문 서술은 양쪽 모두 담당자 몫이므로 측정에서 제외

**측정 항목** (수작업 vs 서비스 각각 기록):
- 초안 골격 작성 (수작업 vs 제안서 템플릿 모듈)
- 평가기준 대응표 작성 (수작업 vs 제안서 템플릿 모듈)
- 담당자 확인 (양쪽 모두 담당자)

**계산식**: (수작업 시간 − 서비스 사용 시간) / 수작업 시간 × 100  
**측정 방법**: 대표 공고 3건을 담당자 1인이 두 방식으로 수행하고 시간 기록 (수작업·서비스 소요시간 모두 **[실측 예정값]**)  
**판정 기준**: SC-001 + SC-002 합산 **50% 이상 단축**  
**판정 주체**: 자동 — Agent 실행 시간 로그 기록 / 사람 — 수작업 골격 작성 시간과 확인 시간 기록 (최종 단축률 산출)  
**측정 시점**: Phase 4(7-8주차)

> 기존 KPI 3 '초안 재사용성(A+B 80%)'은 삭제했습니다. 초안 템플릿은 `[확인 필요]` 자리를 남기는 것이 전제라 문장 단위 재사용 비율로 평가하는 것이 맞지 않기 때문입니다. 템플릿의 유용성은 SC-001 KPI 3 담당자 만족도에서 함께 평가합니다.

## 부록 A. 업무 효율 개선 분석

### 업무 시간 단축

| 작업 단계 | 기존 | AI 지원 | 측정 |
|---------|------|---------|------|
| 공고 검토 및 선택 | 수작업 분석·순위 결정 | Agent 분석·추천 + 담당자 선택 | **[실측 예정값]** |
| 제안서 초안 골격 작성 | 수작업 작성 | Agent 초안 템플릿 + 담당자 본문 작성 | **[실측 예정값]** |
| 합산 | - | - | **[목표값]** 50% 이상 단축 (2.문제정의및서비스계획) |

### 품질 개선
1. **자격요건 누락 방지**: 자격 필터로 부적격 공고를 추천에서 제외하고, 초안 템플릿에 공고 평가항목을 빠짐없이 옮깁니다.
2. **공고별 맞춤 골격**: 담당자 경험과 무관하게 공고 평가항목 기준의 목차에서 작성을 시작합니다.
3. **평가기준 대응 정리**: 평가항목별로 대응 섹션과 기업 근거를 표로 정리하고, 근거가 없는 항목은 `[확인 필요]`로 표시합니다.

### 의사결정 지원
1. **추천 근거 제시**: 자격·역량이 맞는 공고를 근거와 출처(기업·공고의 어느 값인지)와 함께 선별합니다.
2. **데이터 기반 판단**: 적합도 점수와 항목별 근거로 객관적으로 비교합니다.
3. **사람의 최종 결정**: 최종 선택과 확정은 담당자가 수행하며, AI는 조력자 역할입니다.

## 부록 B. 검증 계획

### 정량 평가 (자동 측정 중심, 평가 주체는 KPI 측정 종합표 참조)

**SC-001 (공고 추천)**
- **추천 정확도:** 정답셋 300조합(30 공고 × 10 기업)에 대해 90% 이상. 정답은 담당자 1인이 사전 라벨링한 '추천' 공고(3단계 라벨 중)
- **자격 필터 정확성:** 추천 상위 5건에 '부적격' 공고 0건, Eligibility 판정과 '부적격' 라벨 일치율 함께 기록
- **추천 근거 설명 가능성:** 추천 근거의 출처 확인 비율 95% 이상

**SC-002 (초안 템플릿, 보조)**
- **초안 시작 가능 여부:** 30건 모두 섹션 4개 + 대응표가 파싱 가능한 구조로 생성, 필수 입력 항목 반영률 100%
- **초안 근거성:** 초안 템플릿 30건에서 프로필에 없는 사실 기재 0건

### 정성 평가 (사용자 피드백)

**담당자 인터뷰 (1인)**
- SC-001: 추천 공고 적합도, 입찰 여부 판단 도움 수준, 화면 이해도
- SC-002: 초안 템플릿 목차의 적절성, 템플릿 활용 의향, 골격 작성 시간 절감 체감, 전반 만족도 (5점 척도)

**초안 템플릿 검증**
- 실제 공고 3건에서 생성된 초안 템플릿으로 담당자가 골격 작성을 마칠 때까지의 소요 시간 측정
- 템플릿에 추가하면 좋을 고정 항목 기록 (확장 단계 개선에 사용)

### 최종 검증 (Gate)
- 실제 공고 3건 × 가상 기업 5개 = 15건 End-to-End 테스트
- 통과 기준: 1순위 KPI 3종(추천 정확도, 자격 필터 정확성, 근거 설명 가능성) 달성 필수 + 시간 단축 50% + 보조 KPI 달성 + 담당자 만족도 3.5/5.0 이상
