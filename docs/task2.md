# 나라장터 AI 입찰 어시스턴트 - 문제 정의 및 서비스 기획

## 1. 프로젝트 개요

### 프로젝트명

나라장터 AI 입찰 어시스턴트 - 기업 맞춤 공고 추천 및 제안서 초안 자동 생성 서비스

***

## 2. 문제 정의

### 현재 상황 (As-Is)

입찰 담당자는 나라장터에 올라오는 매일 100~200건의 공고 중에서 자사 역량과 맞는 공고를 일일이 확인해야 한다. 적합 공고를 찾은 후에는 공고문과 제안요청서를 읽으면서 자격요건, 필수 제출서류, 평가기준을 수작업으로 정리해야 한다. 제안서 작성 시에는 이전 제안서를 복사하거나 템플릿을 수정하는 방식으로 진행하는데, 공고마다 요구사항이 다르기 때문에 매번 초안부터 작성해야 한다. 이 모든 업무는 담당자 개인의 경험과 시간에 크게 의존하고 있다.

### Pain Point (문제점)

**시간 손실**: 공고 검토에 하루 2-3시간, 각 공고별 제안서 초안 작성에 추가로 2-3시간이 소요된다. 담당자가 처리할 수 있는 공고 수가 물리적으로 제한되어 있다. 비즈니스 임팩트로는 월 100~200건 공고 중 검토 가능 공고는 30건 내외에 그쳐 적합 공고를 놓치게 된다.

**품질 불일치**: 담당자마다 공고 적합성 판단 기준이 다르고, 제안서도 작성자마다 스타일이 달라 일관성이 낮다. 또한 자격요건이나 평가기준 항목을 놓치는 휴먼에러가 빈번하게 발생한다. 이로 인해 제안서 탈락 중 일부는 필수 항목 누락으로 인한 불합격이 발생한다.

**기회 비용 (가장 치명적)**: 검토하지 못하고 넘어가는 공고 중에 적합한 것이 있을 수 있고, 소수 인력이 반복적인 탐색·정리·초안 작성에 묶여 있어 더 중요한 전략적 업무에 집중할 수 없다. 이는 결국 수주 기회 손실과 담당자 역량 미활용으로 이어진다.

### 기회 요인

공고 분석 -> 매칭 -> 제안서 작성 -> 검토로 이어지는 업무 흐름이 체계적으로 정의되어 있어서 단계별 AI Agent로 자동화할 수 있다. LLM의 발전으로 요구사항을 이해하고 기업 정보와 연결해 설득력 있는 문장을 생성할 수 있게 되었다. 조달청이 입찰공고정보를 공개 API로 제공하고 있어 실제 데이터 기반 검증이 가능하다. 특히 최종 판단은 사람이 하되, 반복적인 탐색·정리·초안 작성만 AI가 담당하는 구조로 설계하면 담당자의 시간을 크게 줄일 수 있다.

## 3. 목표 사용자 (Target User)

공공 입찰에 참여하는 중소 IT 기업의 입찰·영업 담당자

주요 역할: 공고 모니터링, 입찰 참여 여부 판단, 제안서 작성 및 제출

업무 특성: 소수 인원(1~3명)이 매일 100+ 건의 공고를 처리해야 하고, 마감일에 쫓기는 반복 문서 업무 비중이 높음

서비스와의 관계: 담당자의 최종 판단을 대체하지 않고, 공고 선택과 제안서 초안화에 필요한 정보를 빠르고 일관되게 제공하는 조력자 역할

## 4. 프로젝트 목표

### 정성적 목표 (비즈니스 관점)

1. **업무 자동화로 수주 기회 확대**: 공고 탐색·요약·제안서 초안 작성의 반복적이고 시간 소모적인 업무를 AI 기반으로 자동화한다. 결과적으로 같은 인력 투입으로 월 제출 건수를 30건에서 50건으로 확대하여 수주 기회를 극대화한다.

2. **의사결정 품질 향상으로 수주율 개선**: 추천 근거와 자격요건 충족 여부를 명확히 제시해 입찰 참여 여부를 빠르고 객관적으로 판단하도록 지원한다. 이를 통해 낙찰 확률 낮은 공고 사전 필터링과 제안서 필수 항목 누락을 예방하여 낙찰 확률을 향상시킨다.

3. **기술 내재화** (개발팀 학습 목표): LangGraph 기반 멀티 Agent 오케스트레이션 및 Supervisor 패턴 구현으로 실전 AI 시스템 설계 경험을 획득한다.

## 5. 핵심 기능 정의

### 필수 구현 (1차, 8주 안에 완성)

**기능 1: 기업 맞춤 공고 추천 및 분석**

일일 100~200건 공고 중 적합 공고 찾는 시간을 60% 단축해 검토 범위를 확대하기 위해 필요하다. 공고 분석 Agent가 나라장터 공고의 과업내용·자격요건·평가기준을 구조화한 후, 매칭 Agent가 기업 기술·인력·실적과 비교해 유사도를 계산한다. 출력은 공고 목록(제목, 예산, 마감일) + 적합도 스코어(%) + 추천 근거 3-4가지 + 자격요건 충족 여부 형태로 제공된다.

**기능 2: 담당자 승인 기반 공고 선택**

최종 의사결정 권한을 담당자에게 부여해 AI 과신을 방지하고 비즈니스 판단을 우선화하기 위해 필요하다. 추천 결과를 담당자가 직접 검토한 후 제안서를 작성할 공고 1건을 선택하는 Human-in-the-loop 방식으로 구현된다. 출력은 선택된 공고 ID 및 상세정보이다.

**기능 3: 제안서 초안 자동 생성**

공고마다 공통 요소는 자동 생성해 담당자는 고도화·커스터마이징에만 집중하도록 하여 초안 작성 시간을 50% 단축하기 위해 필요하다. 제안서 작성 Agent가 선택된 공고와 기업 정보를 바탕으로 초안을 생성하고 평가기준 대응표를 함께 제시한다. 출력은 마크다운 형식 제안서 초안 + 평가기준 매핑표(담당자가 수정 가능한 형태)이다.

**범위 명확화**: 기능 1~3까지 초안 생성까지 완성. 생성된 초안의 품질 판단과 최종 편집은 담당자 책임.

### 확장 구현 (2차 목표, 향후 진행)

**기능 4: 자동 검증 루프 (미포함)**

검증 Agent가 생성된 제안서 초안을 자동으로 점검하여 필수 항목 누락, 자격요건 불일치 등을 발견한다. 미흡 시 작성 Agent에 재작성을 지시하는 자동 루프를 구성한다. 다만 검증 Agent의 학습과 재작성 로직이 복잡하기 때문에 1차에는 기본 기능 3개에 집중하는 것이 효율적이므로 2차 목표로 미룬다.

## 6. 기대 효과 및 핵심 가치 제안

### 1단계: 시간 효율성 - 공고 검토 및 제안서 초안 시간 50% 단축

**시간 단축 계산 (공고 1건 기준)**

| 단계                | 기존 소요시간       | 개선 후 소요시간     | 단축 효과      |
| ----------------- | ------------- | ------------- | ---------- |
| 공고 분석 + 자격 매칭 검토  | 2시간           | 0.8시간         | 60% 단축     |
| 제안서 초안 작성         | 3-4시간         | 1.5-2시간       | 50% 단축     |
| 담당자 최종 검토         | 0.5시간         | 0.5시간         | 변화 없음      |
| **공고 1건당 총 소요시간** | **5.5-6.5시간** | **2.8-3.3시간** | **50% 단축** |

**월 처리량 확대**:

계산 근거는 공고 1건당 평균 5.5시간 소요 기준이며, 담당자 월 업무시간(약 160시간)을 단순 환산한 추정치이다. 기존에는 160시간 ÷ 5.5시간 = 월 약 29건 처리 가능(1일 약 2건)이었으나, 개선 후에는 160시간 ÷ 3시간 = 월 약 53건 처리 가능(1일 약 5건)이 된다. 결과적으로 같은 인력 투입으로 월 처리량을 30건에서 50건으로 확대할 수 있으며, 이는 약 1.7배~2배 증가이다.

### 2단계: 의사결정 품질 - 객관적 근거 기반 판단

시스템이 제시하는 추천 근거 + 자격요건 분석 + 평가기준 대응 정보를 통해, 담당자의 주관적 판단 의존도를 감소시키고 일관된 선택 기준을 확보한다. 또한 낙찰 가능성 낮은 공고를 사전에 필터링하여 불필요한 제안서 작성 시간을 절감한다. 최종 판단 권한은 사람이 유지하되, 판단에 필요한 객관적 정보는 AI가 제공하는 구조로 운영된다.

### 3단계: 품질 표준화 - 제안서의 일관된 완성도

공고별 맞춤형 초안을 AI로 자동 생성함으로써, 필수 항목 누락을 최소화하여 80% 이상의 필수 항목 포함을 목표로 한다. 또한 담당자 경험·스타일과 무관하게 동일한 수준의 초안을 제공하며, 기존 템플릿 복사 대비 공고 요구사항 맞춤도를 향상시킨다.

### 4단계: 수주 기회 극대화 - 업체의 실질적 메리트

#### ❓ 질문: "왜 우리 회사가 이 서비스를 꼭 써야 하나?"

| 상황            | 현재 상태                             | AI 어시스턴트 도입 후                         | 비즈니스 임팩트                            |
| ------------- | --------------------------------- | ------------------------------------- | ----------------------------------- |
| **적합 공고 발견률** | 일일 100~200건 중 검토 가능한 공고 20~30건  | 시간 단축으로 검토 가능 공고 50~60건으로 확대          | 놓치는 적합 공고 감소 → **수주 기회 증가**         |
| **제안서 품질**    | 담당자 피로도 높음 → 초안 완성도 담당자에 따라 편차 발생 | 일관되고 체계적인 초안 자동 제공 → 휴먼에러 최소화         | 필수 항목 누락으로 인한 탈락 예방 → **낙찰 가능성 향상** |
| **제출 건수**     | 월 10~30건 제출                       | 월 50건 이상 제출 가능                        | 같은 품질의 제안을 더 많이 제출 → **수주 기회 극대화**  |
| **담당자 역할 변화** | 공고 검토·자격 확인·초안 작성에 80% 시간 소진      | 시간 단축으로 전략적 판단(낙찰 확률 검토, 제안서 고도화)에 집중 | 담당자 역할 업그레이드 → **수주 전략 고도화 가능**     |

#### 🎯 핵심 메리트: 세 가지 시너지

1. **양(Quantity)**: 같은 인력으로 월 제출 건수를 2배 증가시켜 기회비용을 극소화한다.

2. **질(Quality)**: 공고별 맞춤형 초안과 자격요건 완벽 검토로 제안 탈락률을 감소시킨다.

3. **판단(Decision)**: 객관적 근거를 제공하여 낙찰 확률 높은 공고만 선별 제출하고 선택과 집중을 이룬다.

**결론**: "검토 시간 단축(양) + 의사결정 품질 향상(판단 기준) + 제안서 일관성(품질)"의 결합으로 단순 제출 수량 증대를 넘어 **수주율 자체를 향상**할 수 있는 환경 조성

| 요소    | 효과                                          |
| ----- | ------------------------------------------- |
| 시간 효율 | 같은 시간에 검토 공고 월 30건 → 50건 (약 1.7배 증가)        |
| 품질 향상 | 각 공고별 제안서 경쟁력 강화 (맞춤형 작성, 필수 항목 80% 이상 포함)  |
| 의사결정  | 자격·평가기준 객관적 분석 → 낙찰 확률 높은 공고 선별 제출          |
| 최종 효과 | 제출 건수 증가 + 제안 품질 향상 + 전략적 선택으로 **수주확률 극대화** |

## 7. 범위 및 제약사항

### 1차 구현 범위 (8주)

**필수 구현**: 실제 IT 용역 공고를 대상으로 기업별 적합 공고 추천(근거 포함) → 담당자 선택 → 제안서 핵심 섹션 초안 생성까지의 전 과정 검증

**미포함**: 검증 Agent의 자동 재작성 루프(2차 목표)

### In Scope (이번 8주에 직접 구현 & 검증)

데이터: 공공데이터포털의 조달청 입찰공고정보서비스 API에서 IT 용역 공고 20~30건을 수집. 기업 데이터는 실제 고객사를 대신해 가상 기업 10개사(각사 기술·인력·실적 정보 포함)로 구성. (초기 개발 단계에서는 5개사로 시작해 파이프라인 검증 완료 후 10개사로 확장)

기술 아키텍처: Supervisor 패턴 기반 멀티 Agent 구조 구현. 공고 분석 Agent -> 매칭 Agent -> 제안서 작성 Agent로 이어지는 파이프라인을 LangGraph로 조율. 담당자의 공고 선택 단계는 Human-in-the-loop으로 설계.

UI 및 배포: Streamlit으로 간단한 데모 대시보드를 만들고, Docker 환경에서 실행 가능하도록 구성.

측정 및 검증: 미리 정의한 정답셋(공고 30건 × 가상 기업 10개사)에 대해 추천 정확도, 초안 커버율, 시간 단축 효과를 정량적으로 측정.

### Out of Scope (이번에는 하지 않음)

API 통합: 나라장터 API 실시간 연동과 자동 수집 스케줄링(크론 작업)은 포함하지 않음. 이번에는 정적인 데이터셋으로 기능 검증에 집중.

입찰 제출 및 예측: 최종 제안서를 나라장터에 자동 제출하는 기능과 낙찰가 예측 모델은 범위 밖.

프로덕션 준비: 보안(인증, 암호화), 성능 최적화(캐싱, 로드 밸런싱), 모바일 지원은 이번 PoC 단계에서는 고려하지 않음.

자동 검증 루프: 검증 Agent의 자동 재작성 로직(기능 4)은 2차 목표이며, 이번에는 포함하지 않음.

### 제약사항

데이터 보안: 실제 고객사의 기업 정보나 제안서 사본은 보안상 사용 불가능하므로, 가상의 기업 프로필과 샘플 제안서로 대체.

공고 수집 한계: API 개발계정의 트래픽 제한과 첨부 문서(HWP, PDF)의 자동 파싱 어려움으로 일부 공고는 수동으로 데이터를 보완해야 함.

기술 선택: LLM은 Claude Sonnet만 사용(OpenAI와의 비교 테스트는 별도). 텍스트 임베딩은 오픈소스 모델(BGE-M3)을 사용해 의존성 최소화.

제안서 품질 보증: AI가 생성한 초안의 최종 품질 판정과 수정은 반드시 담당자(사람)가 수행해야 함. 시스템은 80% 정도 완성된 초안을 제공하는 수준.

일정 경직성: 8주 일정 내에 기능 1~3은 반드시 완성해야 하지만, 기능 4(자동 검증)는 시간이 부족하면 2차 목표로 미룸.

개인정보 보호: 나라장터 공고에 포함된 발주처 담당자 연락처, 제안서에 나타나는 직원명·연락처·이메일 등 개인식별정보(PII)는 시스템에 저장하지 않거나 마스킹 처리. 실제 고객사 정보를 사용하지 않고 가상 데이터로만 학습·검증하므로, 프로토타입 단계에서는 개인정보 유출 위험을 최소화. 향후 실제 환경에 배포할 경우 GDPR·개인정보보호법 준수 체계(암호화, 접근 제어, 감사 로그)를 별도로 구축해야 함.
