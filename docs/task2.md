### 프로젝트 명

나라장터 AI 입찰 어시스턴트 — 기업 맞춤 공고 추천 및 제안서 초안 자동 생성 서비스

1차 구현 범위: 실제 IT 용역 공고를 대상으로 기업별 적합 공고 추천(근거 포함) → 담당자 선택 → 제안서 핵심 섹션 초안 생성·검증까지의 전 과정을 8주 안에 검증

### 배경 및 문제 정의

* 현재 상황 (As-Is):

  * 입찰 담당자가 매일 수백 건의 나라장터 공고를 직접 열람해 자사 역량과 맞는지 판단함

  * 적합 공고를 고른 뒤 공고문·제안요청서를 읽고 자격요건, 제출서류, 평가기준을 수작업으로 정리함

  * 제안서는 매번 이전 제안서를 복사·수정하는 방식으로 처음부터 작성함

  * 전체 과정이 담당자 개인의 경험과 시간에 크게 의존하는 구조임

* Pain Point:

  * 시간: 공고 검토에 하루 2~3시간, 공고별 제안서 초안 작성에 2~3시간이 추가로 소요됨

  * 품질: 담당자마다 판단 기준이 달라 일관성이 낮고, 자격요건·필수 항목 누락 등 휴먼에러가 발생함

  * 비용: 적합 공고를 놓치면 입찰 기회 자체가 사라지며, 소수 인력이 반복 문서 업무에 묶여 핵심 업무에 집중하기 어려움

* 기회 요인:

  * 공고 분석 → 매칭 → 작성 → 검토로 이어지는 업무 단계가 명확해, 역할별 AI Agent로 나눠 자동화 가능

  * LLM이 요구사항을 이해하고 기업 정보와 연결해 문장을 생성할 수 있어 제안서 초안 자동화 가능

  * 조달청이 공공데이터포털로 입찰공고 정보를 개방하고 있어 실제 데이터 기반 검증 가능

  * 사람의 판단이 필요한 공고 선택·최종 검토는 남기고, 반복적인 탐색·정리·초안 작성만 AI가 대체

### 목표 사용자 (Target User)

공공 입찰에 참여하는 중소 IT기업의 입찰·영업 담당자

* 역할: 공고 모니터링, 입찰 참여 여부 판단, 제안서 작성 및 제출

* 업무 특성: 소수 인원이 많은 공고를 처리해야 하고, 마감일에 쫓기는 반복 문서 업무 비중이 높음

* 서비스 역할: 담당자의 판단을 대체하지 않고, 판단에 필요한 정보를 빠르고 일관되게 제공

### 프로젝트 목표

* 정성적 목표

  * 목표 1: 공고 탐색·요약·제안서 초안 작성의 반복 업무 자동화

  * 목표 2: 추천 근거와 자격요건 충족 여부를 제시해 입찰 참여 의사결정 지원

  * 목표 3: LangGraph 기반 멀티 Agent 오케스트레이션 및 하네스 엔지니어링 기술 내재화

* 정량적 목표 (KPI)

| **성과 지표**  | **목표 수치**                                    | **측정 방법**                                | **현재 수준**                    |
| ---------- | -------------------------------------------- | ---------------------------------------- | ---------------------------- |
| 추천 정확도     | 상위 3건 중 적합 공고 비율 70% 이상 (1건 이상 포함 비율 90% 이상) | 공고 30건 × 가상 기업 10개사 정답셋과 추천 결과 비교        | 추천 기능 없음 (전량 수작업 검토)         |
| 제안서 초안 커버율 | 공고 필수 항목 반영률 80% 이상                          | 공고 평가기준·과업 요구사항 기반 체크리스트와 초안 대조          | 초안 없이 수작업 작성                 |
| 업무 시간 단축   | 공고 검토 + 제안서 초안 작성 시간 50% 이상 단축               | 대표 시나리오 3건을 수작업/서비스 사용으로 각각 수행해 소요 시간 비교 | 공고 검토 2~3시간/일, 초안 작성 2~3시간/건 |
| 검증 통과율     | 재작성 2회 이내 검증 Agent 통과율 90% 이상                | 검증 Agent 판정 결과 및 재시도 횟수를 실행 로그로 집계       | 해당 없음 (신규)                   |

### 핵심 기능 정의

1. **기업 맞춤 공고 추천**: 공고 분석 Agent가 공고의 과업내용·자격요건·평가기준을 구조화하고, 기업 매칭 Agent가 기업 정보와 비교해 적합 공고 상위 3~5건과 추천 근거, 자격요건 충족 여부를 제시

2. **담당자 승인 기반 공고 선택**: 추천 결과를 담당자가 검토해 제안서를 작성할 공고를 직접 선택하는 Human-in-the-loop 단계로, 입찰 여부의 최종 판단은 사람이 수행

3. **제안서 초안 생성 및 자기 검증**: 제안서 작성 Agent가 회사소개·수행방안·추진일정·조직구성 초안과 평가기준 대응표를 생성하고, 검증 Agent가 필수 항목 누락·자격요건 불일치를 점검해 미흡 시 재작성을 요청 (Supervisor Agent가 전체 흐름 조율)

### 기대 효과

* **업무 효율화**: 공고 검토 및 제안서 초안 작성 시간 50% 이상 단축

* **품질 향상**: 검증 Agent를 통한 필수 항목 누락 감소, 담당자와 관계없이 일관된 판단 기준 적용

* **비용 절감**: 반복 문서 업무에 투입되는 인력 시간 감소, 적합 공고 누락에 따른 기회비용 감소

### 범위 및 제약사항

* In Scope:

  * 공공데이터포털 조달청 입찰공고정보서비스 API로 IT 용역 공고 20~30건 수집·가공, 기업 데이터는 가상 5개사로 구성

  * Supervisor 기반 멀티 Agent 구조 (공고 분석, 기업 매칭, 제안서 작성, 검증 Agent) 및 담당자 승인 단계

  * Streamlit 데모 UI, Docker 기반 실행 환경

  * 평가셋 기반 추천 정확도·초안 커버율·검증 통과율 측정

* Out of Scope:

  * 나라장터 API 실시간 연동 및 자동 수집 스케줄링

  * 실제 입찰 제출 기능, 낙찰가 예측

  * 프로덕션 수준 보안·성능 최적화, 모바일 지원

* 제약사항:

  * 실제 기업 정보·제안서는 보안상 사용 불가 → 기업 정보는 가상 데이터로 대체

  * API 개발계정 트래픽 제한 및 첨부문서(HWP 등) 형식에 따라 일부 공고는 수동 보완

  * LLM은 Claude만 사용하며, 임베딩은 별도 오픈소스 모델(BGE-M3) 사용

  * 8주 일정상 1차 목표는 기능 1·2 완성, 기능 3(제안서 작성·검증 루프)은 2차 목표로 단계적 구현

  * 제안서 품질의 최종 판단은 사람의 검토가 필요 (AI는 초안 작성까지 담당)
