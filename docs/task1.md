## 1. 현재 보유 역량

### Python: 중급
- **가능:** pandas로 CSV·엑셀 데이터 불러오기, 결측치·중복 처리, 형식 변환 등 전처리 스크립트 작성
- **보완 필요:** API 서버 개발, 배포·로그 모니터링

### AI/ML: 초·중급
- **가능:** 정형 데이터 전처리 → scikit-learn 분류 모델 학습 → 정확도 등 지표로 평가
- **보완 필요:** 모델 서빙, 성능 튜닝

### LLM 활용: 초·중급
- **가능:** Claude로 문서 요약·분류, LangChain으로 프롬프트 → LLM 호출 기본 체인 구성
- **보완 필요:** 프롬프트 버전 관리, 출력 품질 평가

### RAG/Agent: 초급
- **가능:** AI 부트캠프에서 PDF 문서 로딩 → 텍스트 분할 → 벡터 저장 → 질의응답까지 기본 파이프라인 실습 (단일 체인 수준)
- **보완 필요:** 여러 Agent 간 역할 분리 및 상태 관리, 작업 분해·조건 분기·검증 루프를 포함한 다단계 Agent 설계

## 2. 학습 필요 영역

**목표:** 단순 질의응답형 RAG 애플리케이션이 아닌, 하나의 요청을 스스로 분해해 여러 Agent가 협업·검증하며 처리하는 구조

### 반드시 필요 (Must)
- **LangGraph 기반 계층형 멀티 Agent 설계·구현**
  - Supervisor가 요청을 하위 작업으로 분해해 역할별 Sub-Agent에 위임
  - 하위 Supervisor를 둔 2단 계층 구성, 공유 State 기반 흐름 제어
  - 1순위 도메인 예시: 공고 분석 / 기업 정보 매칭 / 제안서 초안 작성 / 검토 Agent
- **독립 작업 병렬 실행 및 결과 병합**
  - 여러 공고·조항을 동시 처리한 뒤 Supervisor가 취합 및 정합성 확인
- **Agent 고급 패턴 적용**
  - 검증 Agent 기반 자기 검증·재작성 루프
  - Human-in-the-loop 사용자 승인 흐름
- **하네스 엔지니어링**
  - 프롬프트 표준화, 도구 호출 규약, 출력 스키마 검증 및 재시도 제한
  - 문서 검색(RAG)은 목표가 아니라 Agent가 호출하는 도구 중 하나로 구성

### 있으면 좋음 (Nice to have)
- **Agent 실패 대응**
  - 도구 호출 실패·검증 미통과 시 재시도 및 폴백 경로
  - 무한 루프 방지를 위한 단계 상한
- **상태 저장 및 중단 지점 재시작**
  - checkpoint 기반으로 장기 실행 흐름 복원
  - 승인 대기 후 이어서 실행
- **Agent 실행 관제**
  - 단계별 실행 트레이스 및 토큰 비용 로깅으로 어느 Agent에서 실패했는지 추적

## 3. 기술 스택 선호도

### 필수 스택
- **LLM:** Claude → 긴 문서 처리, Agent 구현에 적합
- **임베딩:** BGE-M3 → 한국어 지원, 무료 오픈소스
- **프레임워크:** LangChain + LangGraph → 도구·검색 계층 구성 및 계층형 Agent 흐름 제어 (State·조건 분기·checkpoint 지원)
- **Vector DB:** Chroma → 사용이 쉽고 예제가 풍부함
- **UI:** Streamlit → Python만으로 빠른 PoC 시연
- **인프라:** Docker → 개발 환경 통일, 배포 용이
- **협업:** GitHub → 버전 관리, 팀 협업

### 확장 (여유 시 적용)
- **API:** FastAPI → UI와 AI 로직 분리, 서비스 확장 시
- **ML:** scikit-learn → 분류·스코어링 보조가 필요할 때

## 4. 프로젝트 관심 도메인

### 1순위: 금융·공공
- 기존 경력 기반 / 진행 중인 프로젝트와 연계 / AI 자동화 수요 높음

#### 관심 업무 후보 (다음 Task에서 1개로 확정)

3. 금융 약관·계약서 주요 조항 비교 및 변경점 검토

### 2순위: 자체 서비스 (신기술 플랫폼)
- 신기술 빠른 적용 / 빠른 시장 진입, 자율적 개발 환경

## 5. 8주 목표 설정

### 기술 목표
LangGraph 기반 계층형 멀티 Agent 직접 설계·구현, 하네스 엔지니어링 및 오케스트레이션 역량 확보

#### 완료 기준
- **오케스트레이션:** 하나의 요청을 Supervisor가 하위 작업으로 분해 → 역할별 Sub-Agent에 위임(일부 병렬) → 결과 취합 → 검증 Agent 통과까지 자율 동작
- **하네스:** 프롬프트 템플릿화, 도구 호출 규약, 출력 스키마 검증·재시도 제한 로직 구현
- **도구 계층:** 문서 검색을 Agent 도구로 제공하여 근거(출처) 제시, 단계별 실행 트레이스 및 평가 로그 저장

### 비즈니스 목표
도메인 업무 자동화 프로토타입 완성

#### 완료 기준
도메인 문서 20~50건 기준, 핵심 과제 20개 중 80% 이상을 근거와 함께 산출물로 생성 (사람 개입은 최종 승인 단계로 한정)

### 성장 목표
RAG/Agent 초급 → 중급 (단일 체인 구현 수준 → 멀티 Agent 오케스트레이션 설계 가능)

#### 완료 기준
외부 도움 없이 Agent 구조 설계·구현·평가 가능, Docker 기반 데모 + GitHub 포트폴리오 완성
