## 1. 구현 범위

| 구분 | 기능 | 상태 | 비고 |
| --- | --- | --- | --- |
| **핵심 검증** | 공고 추천 (룰 필터·점수 → RAG 순위·근거) | 구현·실행 확인 | KPI 1순위 대상 |
| **핵심 검증** | 근거 출처 검증 (원문 대조) | 구현·실행 확인 | 환각 근거 미노출 |
| 필수 | HITL ① 공고 선택 → 제안서 초안(Jinja2 템플릿) | 구현·실행 확인 | 문장 생성 없음, 빈 곳은 `[확인 필요]` |
| 보조 | 업체 로그인·SQLite 작업 이력 | 구현·실행 확인 | KPI 평가 대상 아님 |
| 2차 목표 | 검증 Agent, HITL ②, KPI 자동 평가 스크립트 | 미구현 | 7. 다음 단계 참고 |

## 2. 워크플로우

```
[로그인] → filter_and_score → rag_recommend → select_tender(HITL ①, interrupt) → extract_criteria → build_proposal_template
              룰 500건→10건       10건 PDF+LLM        사용자 선택 대기·재개          LLM 평가항목 추출      Jinja2 초안
```

- **Supervisor (규칙 기반):** State에서 아직 비어 있는 단계를 찾아 해당 Worker로 분기하고, Worker는 작업 후 Supervisor로 복귀합니다. 무한 루프 방지를 위해 라우팅은 최대 12회로 제한합니다.
- **HITL ①:** `select_tender`에서 `interrupt()`로 그래프를 멈추고, `/api/select` 요청이 오면 `Command(resume=공고번호)`로 재개합니다. 추천 목록에 없는 공고번호는 거부합니다.
- **폴백:** LLM 키가 없으면 `rule_only`, LLM 출력 검증에 실패하면 `rule_fallback`으로 룰 순위를 그대로 사용합니다. 평가항목 추출에 실패하면 기술·가격 평가 비율 필드(`techAbltEvlRt`, `bidPrceEvlRt`)로 대체합니다.
- **이력:** 단계별 결과(추천·선택·제안서)를 SQLite에 저장합니다. 저장에 실패해도 그래프는 계속 진행합니다.
- **사용 기술:** LangGraph `StateGraph`·`interrupt`·`InMemorySaver`, FastAPI, SQLite

## 3. 주요 모듈

| 모듈 | 역할 | 동작 원리 | 주요 기술 |
| --- | --- | --- | --- |
| `app/tools/loaders.py` | 데이터 정규화 | 공고번호별 마지막 차수만 남기고 취소공고 제외, 금액 변환, 개인정보 필드 5개 제거 | Python, csv/json |
| `app/tools/rules.py` | 룰 필터·점수 | 하드 필터 H1(PDF)·H3(업종)·H4(참가 제한)·H5(지역)·H6(금액)으로 제외 → 소프트 점수 S1~S4 가중합(0.35/0.30/0.20/0.15)으로 0~100점 → 상위 10건 | 순수 함수 (LLM 미사용, 항상 같은 결과) |
| `app/tools/pdf.py` | PDF 처리 | 첨부 PDF 캐시 다운로드 → 페이지별 텍스트 추출 → 500자 청크 (청크마다 파일명·페이지 유지) | httpx, PyMuPDF |
| `app/tools/retrieval.py` | 청크 검색 | 업체 역량 키워드 + 고정 질의 3개(참가자격·과업 범위·평가 배점)로 검색 후 중복 제거 | 키워드 겹침(기본) / BGE-M3(옵션) |
| `app/tools/llm.py` | RAG 순위·평가항목 추출 | Pydantic 스키마로 구조화 출력, 실패 시 최대 2회 재시도, 후보 누락·중복이면 검증 실패 처리 | Azure OpenAI gpt-4.1, temperature=0 |
| `app/tools/evidence.py` | 근거 출처 검증 | PDF 인용은 해당 파일·페이지 청크에 원문이 있는지, 필드 근거는 실제 필드 값과 일치하는지 대조 → 통과분만 노출, 2개 미만이면 룰 근거로 보충 | 문자열 정규화 대조 |
| `app/tools/proposal.py` | 제안서 초안 | 평가항목별로 업체 실적·인력을 매핑해 고정 템플릿에 값만 삽입 | Jinja2 |

## 4. 주요 문제 해결

| 이슈 구분 | 문제 상황 및 원인 | 리서치 및 해결 과정 |
| --- | --- | --- |
| **프롬프트** | LLM이 공고서에 없는 문장이나 값을 근거로 제시함 (환각) | **리서치:** RAG 출처 표기·Grounding 검증 사례 조사<br>**적용:** 근거마다 file·page·quote를 받도록 스키마를 만들고, 원문과 대조하는 `check_evidence_sources` 후처리를 추가함 → 검증에 실패한 근거는 노출하지 않음 |
| **도구 연동** | 구조화 출력 파싱 실패, 후보 공고 누락·중복 응답 | **리서치:** LangChain `with_structured_output` + Pydantic 스키마 강제 방법 확인<br>**적용:** 최대 2회 재시도하고, 후보 수가 맞지 않으면 룰 순위로 폴백 |
| **데이터** | 같은 공고번호가 변경·취소 차수로 여러 건 존재 | **리서치:** 나라장터 API `bidNtceOrd`·`ntceKindNm` 필드 의미 확인<br>**적용:** 공고번호별 마지막 차수만 남기고 취소공고를 제외함 (500건 → 443건) |
| **데이터** | 지역 제한 공고의 허용 지역이 필드에 없음 | **리서치:** `rgnLmtBidLocplcJdgmBssNm` 값 분석<br>**적용:** 공고별 허용 시·도 수동 매핑표(`region_limits.csv`)를 도입하고, 매핑에 없는 공고는 보수적으로 제외 |
| **보안** | 공고 원본에 발주처 담당자 이름·연락처 포함 | **적용:** 로드 시점에 개인정보 필드(`ntceInsttOfclNm` 등 5개)를 제거 |

### 5-2. 공고 수 퍼널

2·3번 문서의 "PDF 보유 437건"은 원본 500건 기준이고, 실제 추천 대상은 차수·취소공고를 정리한 443건 기준입니다.

| 단계 | 건수 | 설명 |
| --- | --- | --- |
| 원본 | 500 | 공고 파일 전체 (PDF 보유 437건 = 2·3번 문서 기준) |
| 정규화 | 443 | 공고번호 고유 472건 → 마지막 차수만 남기고 취소공고 제외 |
| H1 PDF 보유 | 410 | 443건 중 PDF 첨부가 있는 공고 |
| 하드 필터 통과 | 87 | 제외 사유: H1 33 · H3 331 · H4 0 · H5 44 · H6 77 (한 공고가 여러 규칙에 걸리면 각각 집계) |
| 추천 | 10 | 소프트 점수 상위 10건 → LLM 순위·근거 |

### 5-4. 룰 경로 vs LLM 경로

| 항목 | 룰 경로 (`rule_only`) | LLM 경로 (`rag`) |
| --- | --- | --- |
| 처리 시간 | 0.08초 (443건 필터·점수) | 추천 61.6초 (PDF 청크 0.8초 + LLM 약 60초), 선택→초안 4.7초 |
| 상위 3건 | ① 스마트팜 심포지엄 ② 팁스 데모데이 ③ USG 직무박람회 | ① 스마트팜 심포지엄 ② 팁스 데모데이 ③ 한미친선 한마음축제 (2회 실행 모두 동일) |
| 근거 | 필드 값 기반 3~4개 (출처 100%) | 노출 근거 35개 중 PDF 인용 13개 (10건 모두 PDF 청크 확보) |
| 추가 정보 | 없음 | 참가자격 의심 항목(`qualification_flags`): 10건 모두 직접생산확인증명서 등 확인 필요 표시 |
| 폴백 발생 | 해당 없음 | 2회 실행 중 0회 |

**LLM 경로의 한계 (실측):** 출처 검증 전 LLM 원출력의 근거 39개 중 **25개(64%)만 원문 대조를 통과**했습니다(필드 19/28, PDF 인용 6/11). 화면에는 통과한 근거만 노출되므로 표시되는 근거의 출처 확인율은 100%이지만, 원출력 기준으로는 KPI 목표(95%)에 미달합니다. 따라서 **현재 PoC의 판정은 룰 경로와 출처 검증 후처리를 기준으로 하고**, LLM 원출력 품질 개선은 다음 단계로 넘깁니다.

### 6-2. KPI 대비 PoC 판정

| KPI (2·3번 문서) | 목표 | PoC 측정 결과 | 판정 |
| --- | --- | --- | --- |
| 자격 필터 정확성 | 부적격 0건 | 규칙별 단위 테스트 통과, 제외 사유를 규칙 단위로 집계 | 로직 검증 완료 (라벨 대조는 Phase 4) |

| 추천 정확도 | Hit Rate@3 80%↑, Precision@3 0.67↑ | 미측정 (정성 확인: C001 상위 3건 모두 업종·예산 일치) | Phase 4 (업체 41~50 라벨링) |
| 시간 단축 | 50%↑ | 추천 약 62초 + 초안 약 5초 (수작업 대조군 미측정) | Phase 4 |
| 초안 근거성 | 없는 사실 0건 | 템플릿 값 삽입 방식이라 구조적으로 보장, 빈 곳 7곳 `[확인 필요]` | 충족 |

**PoC 동작 판정 기준:** ① 로그인 → 추천 → 선택 → 초안 → 이력까지 API가 끊김 없이 완료될 것, ② 폴백 없이 LLM 경로가 동작할 것, ③ 노출 근거가 모두 원문 대조를 통과할 것, ④ 단위 테스트가 전부 통과할 것. 이번 실행에서 4가지 모두 충족했습니다.
